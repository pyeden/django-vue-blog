# 18. 头像上传

## 本章目标

- 配好 `MEDIA_URL` 和 `MEDIA_ROOT`，让上传文件有固定落点和访问地址。
- 在开发环境让 Django 自己服务媒体文件，生产环境交给 nginx。
- 写 `POST /api/profile/avatar/`，接收 multipart 文件并保存到 `Profile.avatar`。
- 在个人资料页完成选择文件、上传、立即刷新头像的闭环。

## 原教程怎么做

原教程先在 `settings.py` 增加 `MEDIA_URL` 和 `MEDIA_ROOT`，再在根 `urls.py` 用 `static()` 把媒体目录挂到开发服务器上。上传表单是普通的 `POST` 表单，模板里写 `enctype="multipart/form-data"`，视图接收 `request.FILES`，存进 `Profile.avatar` 后重新渲染页面。它还会讲 `upload_to` 的作用：文件不是直接丢在 `media/` 根目录，而是按字段配置的子目录归档。

## 本实作怎么做

媒体配置在 `backend/config/settings.py`：

```python
MEDIA_URL = os.environ.get("DJANGO_MEDIA_URL", "/media/")
MEDIA_ROOT = Path(os.environ.get("DJANGO_MEDIA_ROOT", BASE_DIR / "media"))
```

模型字段在 `backend/accounts/models.py`，`upload_to="avatars/"` 决定文件落在 `media/avatars/` 下。Django 会自动处理重名，不会覆盖已有文件。

开发环境的媒体路由在 `backend/config/urls.py`：

```python
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

这段只在 `DEBUG=True` 时生效，生产环境不能靠 Django 发图片，否则性能很差。部署时 nginx 用 `alias` 把 `/djangovueblog/media/` 指到 release 的 `media/` 目录，同时保证 worker 用户有读权限。

上传接口在 `AvatarUploadView`：

```python
profile, _ = Profile.objects.get_or_create(user=request.user)
avatar = request.FILES.get("avatar")
if avatar is None:
    return Response({"detail": "缺少 avatar 文件。"}, status=400)
profile.avatar = avatar
profile.save(update_fields=["avatar"])
return Response(ProfileSerializer(profile, context={"request": request}).data)
```

`ProfileSerializer` 的 `get_avatar` 会调用 `build_absolute_uri`，所以前端拿到的是完整地址，不依赖当前页面路径。前端 `frontend/src/api/index.js` 的 `uploadAvatar(file)` 用 `FormData` 追加字段，再交给 axios；浏览器会自动带 boundary，千万不要手写 `Content-Type: multipart/form-data`，否则后端收不到文件。

资料页 `frontend/src/views/ProfileView.vue` 用一个隐藏的 `<input type="file" accept="image/*">`，点“更换头像”触发选择，`onAvatar` 上传成功后更新预览并 `auth.refresh()`，顶栏头像也会跟着变。

## 踩坑与差异

- 前端手动设置 multipart 的 `Content-Type` 是常见错误；让浏览器自己生成 boundary。
- 当前没有限制文件大小和像素，也没有压缩或裁剪。ImageField 只验证它是不是能识别的图片，不能挡住几十兆的大图。生产环境建议在 nginx 设 `client_max_body_size`，后端再加尺寸校验。
- 旧头像不会自动删除，时间长了 `media/avatars/` 会有孤儿文件；个人博客可以接受，正式项目应做清理任务。
- 原教程用表单直接提交并刷新整页；这里是异步上传，只更新局部状态，体验更好，但也要求前端正确处理失败提示。
- 生产环境若忘记给 `media/` 加读权限，页面头像会 403，而 API 本身仍然正常，容易误判成上传失败。

头像不只在资料页出现。文章卡片、评论、顶栏都会读 `author.avatar` 或 `user.avatar`，这些字段由各自的序列化器返回绝对地址。上传接口只更新当前用户，不能替别人换头像，权限是 `IsAuthenticated`。如果以后要支持裁剪，建议在前端先裁再传，后端只存最终图，避免把原图和处理逻辑都压在 Django 上。
