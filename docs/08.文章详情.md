# 08. 文章详情

## 本章目标
- 用 slug 而不是 id 定位文章。
- 详情接口返回 `body_html`、`toc`、`liked` 并自增浏览量。
- 用 `ArticleDetailView` 渲染标题、封面、标签、正文和评论。
- 处理中文 slug 与路由参数变化。

## 原教程怎么做
原教程新增 `article_detail(request, id)`，用 `ArticlePost.objects.get(id=id)` 取文章，传进 `detail.html`，模板里直接输出 `{{ article.title }}` 和 `{{ article.body }}`；路由是 `article-detail/<int:id>/`。

## 本实作怎么做
详情仍由 `ArticleViewSet` 提供，但 `lookup_field = "slug"`，并允许中文和常见字符：
```python
lookup_field = "slug"
lookup_value_regex = r"[^/.]+"
```
`retrieve()` 在返回前自增浏览量，用 `F()` 避免并发覆盖：
```python
def retrieve(self, request, *args, **kwargs):
    instance = self.get_object()
    Article.objects.filter(pk=instance.pk).update(total_views=F("total_views") + 1)
    instance.total_views += 1
    serializer = self.get_serializer(instance)
    return Response(serializer.data)
```
`backend/blog/serializers.py` 的 `ArticleSerializer` 在详情里多给三个字段：`body_html`（模型保存时已渲染）、`toc`（`extract_toc(body)`）、`liked`（当前登录用户是否点过赞）。`author` 只返回 `username` 和 `avatar`，`column` 返回 `{title, slug}`。

前端 `frontend/src/views/ArticleDetailView.vue` 用 `fetchArticle(slug)` 取数据，再并行加载评论。正文交给 `MarkdownBody`，目录交给 `TocRail`：
```vue
<MarkdownBody :html="article.body_html" />
...
<TocRail :toc="article.toc || []" />
```
作者判断是 `auth.username === article.author.username`，管理员用 `auth.isStaff`，两者都能看到“编辑”和“删除”按钮。

## 在 MacBook 上操作
```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py runserver 127.0.0.1:8000
cd ../frontend
npm run dev
```
打开 <http://127.0.0.1:5173/article/写作这件小事>。接口层用 `encodeURIComponent(slug)` 编码，所以中文 slug 不会把路径截断。直接请求 API 时也要编码：
```bash
curl -s "http://127.0.0.1:8000/api/articles/$(python3 -c "import urllib.parse;print(urllib.parse.quote('写作这件小事'))")/"
```
返回的 JSON 里应包含 `body`、`body_html`、`toc`、`liked`，并且 `total_views` 每次请求加一。

## 验证
刷新详情页，页面上的浏览量会增加；正文中的标题、代码块、表格正常显示；右侧目录能点击跳转。请求不存在的 slug 返回 404，前端显示“文章不存在”。登录后点过赞再刷新，`liked` 应为 `true`。

## 踩坑与差异
- 原教程用自增 id，本实作改用 slug；好处是链接可读，代价是标题改名后旧链接会失效，所以编辑时 `slug` 设为只读。
- 中文 slug 不需要额外转码，但前端必须 `encodeURIComponent`，curl 也要 URL 编码。
- 浏览量按请求次数累加，不是独立访客数；要精确统计得另做 IP 或用户去重。
- `ArticleDetailView` 监听 `route.params.slug`，从一篇详情跳到另一篇时会重新加载，不会停在旧文章。除此之外本章没有遇到额外问题。
