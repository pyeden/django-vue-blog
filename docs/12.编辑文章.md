# 12. 编辑文章

## 本章目标
- 用 PATCH 做部分更新，不要求提交全部字段。
- 让 `EditArticleView` 先取文章再复用编辑器。
- 处理标签“清空”和“不传”的区别。
- 保证非作者不能修改。

## 原教程怎么做
原教程写 `article_update(request, id)`：先 `get(id=id)`，POST 时把 `request.POST['title']`、`request.POST['body']` 赋回文章再 `save()`，GET 时把文章对象传进 `update.html`，模板用 `value="{{ article.title }}"` 和 textarea 回填旧内容。

## 本实作怎么做
更新由 `ArticleSerializer.update` 处理：
```python
def update(self, instance, validated_data):
    tags = validated_data.pop("tags", None)
    for key, value in validated_data.items():
        setattr(instance, key, value)
    instance.save()
    if tags is not None:
        instance.tags.set(tags)
    return instance
```
这里有两个细节：`instance.save()` 会重新执行模型的 `save()`，所以 `body_html` 会跟着新正文重新渲染；`tags` 用 `None` 表示“这次没传，保持原样”，用空数组表示“明确清空”。`column` 传 `null` 表示取消栏目。

前端 `frontend/src/views/EditArticleView.vue` 先 `fetchArticle(slug)`，成功后把文章对象交给 `ArticleEditor`：
```vue
<ArticleEditor v-else-if="article" :article="article" />
```
`ArticleEditor` 监听 `props.article`，把 `title`、`body`、`column.slug`、`tags` 填进表单。保存时 `isEdit` 为真，走 `updateArticle(props.article.slug, payload)`，成功后跳回详情页。路由是 `/edit/:slug`，`meta.requiresAuth` 只保证登录，是否本人由服务端权限判断。

`PATCH` 允许只传一个字段，DRF 会自动把序列化器设成 `partial=True`，所以脚本改标题不用带正文。`column=null` 会走 `ColumnField.to_internal_value` 返回 `None`，把栏目清掉；不传 `column` 则保持原值。

## 在 MacBook 上操作
登录作者账号，在文章详情点“编辑”，或直接打开 <http://127.0.0.1:5173/edit/写作这件小事>。改标题、正文、标签或栏目，点“保存修改”。应提示“文章已更新”并回到详情页。接口调试用 PATCH：
```bash
curl -s -b /tmp/blog-cookies.txt -X PATCH \
  -H "X-CSRFToken: <cookie里的值>" \
  -H "Content-Type: application/json" \
  -d '{"title":"改过的标题"}' \
  http://127.0.0.1:8000/api/articles/<slug>/
```
只传 `title` 也可以，其他字段保持不变。

`EditArticleView` 只负责取数据和错误状态，表单逻辑全在 `ArticleEditor` 里；`isEdit` 由 `props.article.slug` 判断，所以同一个组件既能新建也能编辑。编辑页的封面预览用已有 `cover`，选新文件后本地预览替换，保存时再上传；不选文件就不会重复上传。

## 验证
PATCH 返回 200，详情页标题已变，`updated` 时间更新；改正文后 `body_html` 应同步变化，旧 HTML 不会残留。slug 不会因为改标题而变化，旧链接仍可访问。非作者 PATCH 返回 403，`backend/blog/tests.py` 的 `test_author_and_staff_can_update` 与 `test_non_author_cannot_update_or_delete` 覆盖了这两侧。

还要检查标签清空：把标签全部删掉再保存，详情页标签区应消失，而不是保留旧标签；这说明空数组走到了 `tags.set([])`。

## 踩坑与差异
- 原教程用 POST 覆盖 title/body；本实作用 PATCH，允许只改一个字段，编辑器仍然提交完整表单。
- 标签不传和传空数组语义不同：不传保留，空数组清空；前端每次都传当前标签数组，所以删光标签会真的清空。
- `slug` 是只读字段，修改标题不会改链接；这是有意的取舍，避免旧链接失效。
- 编辑页路由只要求登录，不校验作者；不要在路由守卫里假装做了权限，真正的 403 在服务端。
- 并发编辑没有做版本号或 `updated` 冲突检测，两个人同时保存会以后提交的为准。
- 编辑页复用 `ArticleEditor`，新建和编辑的差别只在 `isEdit` 和初始值；如果以后加草稿，别把两套表单分开写。
- 封面更新走 `uploadArticleCover`，它只改 `cover` 字段，不会触发正文重新渲染。

编辑页的取消按钮走 `router.back()`，从外部直接打开时可能没有上一页；需要更稳可以改成回详情页。

## 小结
文章的新增、查看、修改、删除都齐了，接下来处理用户体系：登录、退出和会话。
