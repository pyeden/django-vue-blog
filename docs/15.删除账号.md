# 15. 删除账号

## 本章目标
- 新增 `POST /api/auth/delete/`。
- 删除前要求输入当前密码。
- 先退出会话再删除用户。
- 在资料页提供入口并说明级联后果。

## 原教程怎么做
原教程写 `user_delete(request, id)`，用 `@login_required` 限制登录，只接受 POST，比较 `request.user == user`，然后 `logout()` 再 `user.delete()`，返回列表；入口放在导航下拉框，用 layer 弹窗确认。

## 本实作怎么做
接口在 `backend/accounts/views.py`：
```python
class DeleteAccountView(APIView):
    permission_classes = [IsAuthenticated]

    def post(self, request):
        password = request.data.get("password") or ""
        if not request.user.check_password(password):
            return Response({"password": ["密码不正确。"]}, status=status.HTTP_400_BAD_REQUEST)
        user = request.user
        logout(request)
        user.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)
```
它不接受用户 id，只删 `request.user`，所以不存在“删别人”的参数。`check_password` 是额外的一道确认：即使 session 被借用，不知道密码也删不掉。`logout()` 放在 `delete()` 前面，避免用户对象没了但会话还挂着。

路由在 `backend/accounts/urls.py`：`path("auth/delete/", DeleteAccountView.as_view(), name="auth-delete")`。前端 `frontend/src/api/index.js` 的 `deleteAccountRequest(password)` POST 到 `/auth/delete/`；`ProfileView.vue` 的入口：
```js
if (!window.confirm('确定删除账号吗？你的文章和评论会一起删除，且不可恢复。')) return
const password = window.prompt('输入当前密码以确认删除：')
if (!password) return
await deleteAccountRequest(password)
auth.user = null
toast.success('账号已删除')
router.push({ name: 'home' })
```
级联关系由模型决定：`Article.author` 是 `CASCADE`，`Comment.user` 是 `CASCADE`，`Profile`、`ArticleLike` 随用户删除；`Notification` 作为接收者时删除，作为 actor 时被置空。删账号等于把这个人写过的东西一起清掉。

`DeleteAccountView` 没有 `get` 方法，GET 请求会 405；删除只能 POST。密码字段缺失时 `request.data.get("password")` 得到空字符串，`check_password("")` 返回 False，按密码错误处理。

## 在 MacBook 上操作
登录后打开 <http://127.0.0.1:5173/profile>，点“删除账号”，确认框点确定，再输入当前密码。成功后会回到首页，右上角变回“登录/注册”。接口调用：
```bash
curl -s -b /tmp/blog-cookies.txt -H "X-CSRFToken: <cookie里的值>" \
  -H "Content-Type: application/json" \
  -d '{"password":"当前密码"}' \
  http://127.0.0.1:8000/api/auth/delete/
```
成功状态是 204，响应体为空；密码错误返回 400，错误键是 `password`。

级联范围要提前想清楚：`Article.author` 是 `CASCADE`，文章没了，文章下的评论、点赞、通知也跟着没；`Comment.user` 是 `CASCADE`，这个人在别人文章下的评论也会删；`Profile` 是一对一 `CASCADE`。如果以后想保留文章只把作者置空，需要把 `author` 改成 `SET_NULL` 并允许 `null`，那是另一种产品决策。

## 验证
建议用一个临时账号验证：先发一篇文章、留一条评论，再删除账号；随后 `/api/auth/me/` 返回 `user: null`，首页不再有该账号的文章，评论树里也找不到它的评论。用 shell 检查 `User.objects.filter(username=...).exists()` 应为 `False`，对应的 `Profile`、`Article`、`Comment` 都不存在。现有 `backend/accounts/tests.py` 没有覆盖删除账号，这是后续可以补的测试点。

如果删除后仍能访问 `/profile`，说明前端没清 `auth.user` 或路由守卫没重新跑；刷新页面应跳登录。`logout()` 已经让 session 失效，旧 cookie 再请求写接口会 403。

## 踩坑与差异
- 原教程只校验 `request.user == user`；本实作不接收 id，并且额外要求当前密码，安全性更高。
- 原教程用 layer 弹窗；本实作用 `window.confirm` + `window.prompt`，交互朴素但不需要额外组件。
- 删除是不可逆的，确认文案必须明确写出“文章和评论会一起删除”；不要做成一个没有提示的小链接。
- `logout()` 必须在 `user.delete()` 前调用；顺序反了会拿不到当前会话用户。
- 删除账号没有软删除和恢复窗口；如果以后要支持恢复，应该先禁用账号并保留数据，而不是直接 `delete()`。
- 接口返回 204 后，前端不再需要请求 `me`，直接跳首页即可。

如果以后要支持团队账号，删除前应检查是否是最后一个管理员，避免把后台锁死。

## 小结
到这里，文章、评论、登录、注册、删号的闭环已经完成；下一章处理忘记密码时的重置邮件。
