# 28. 标签

## 本章目标

- 用 `django-taggit` 给文章挂多对多标签，不自己写中间表。
- 自定义序列化字段，让标签在 JSON 里是 `["Django", "Vue"]` 这样的字符串数组。
- 提供标签列表和按标签过滤的接口，并在编辑器里做标签输入。
- 知道当前按 slug 过滤存在大小写差异，侧栏的英文标签链接可能查不到文章。

## 原教程怎么做

原教程安装 `django-taggit`，把 app 加进 `INSTALLED_APPS`，在文章模型里加 `TaggableManager()`。发布文章时把标签字符串写进去，列表和详情用模板遍历 `article.tags.all` 显示。标签过滤则在列表视图里按标签名筛选，并提醒要 `distinct()`，否则一篇文章有多个标签时会出现重复行。

## 本实作怎么做

依赖和配置在 `backend/requirements.txt` 与 `backend/config/settings.py`，`taggit` 已加入 `INSTALLED_APPS`。模型字段在 `backend/blog/models.py`：

```python
tags = TaggableManager(blank=True)
```

`blank=True` 允许文章没有标签。`TaggableManager` 自动维护标签表和关联表，不需要写 `ArticleTag` 中间模型。

序列化器里自定义了 `TagsField`：

```python
def to_representation(self, value):
    return [tag.name for tag in value.all()]

def to_internal_value(self, data):
    ...
    return cleaned
```

读出来是名字数组，写进去接受字符串数组，去空、去重。创建文章时 `create()` 先 `pop("tags")`，创建 Article 后 `article.tags.set(tags)`；更新时只有传了 `tags` 才覆盖，没传就保持原样。

标签列表 `TagListView` 不分页，返回 `{name, slug}`。文章列表的 `get_queryset()` 支持 `?tag=`：

```python
queryset = queryset.filter(tags__name__in=[tag]).distinct()
```

`distinct()` 是必须的，否则一篇文章如果同时命中多个标签条件会产生重复行；当前只传一个标签，但保留它是为了以后扩展。

前端 `TagInput.vue` 用回车或逗号添加标签，最多 10 个，退格可以删最后一个；`ArticleEditor.vue` 把数组直接放进 payload。`TagView.vue` 用 `/tag/:slug` 复用 `ArticleFeed`，把 `tag` 作为过滤条件；侧栏的标签云来自 `meta.tags`，每个 chip 指向标签页。

## 在 MacBook 上操作

```bash

```

## 验证

- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_column_and_tag_filter`：`?tag=python` 应只返回带该标签的文章。
- 创建文章时传 `tags: ["Django", "test"]`，返回的 `tags` 应去重且保持顺序。
- 更新文章不传 `tags`，原标签不应被清空。
- 同一篇文章重复加同一个标签，数据库里只保留一条关联。

## 踩坑与差异

- 原教程在模板里遍历标签；这里由 `TagsField` 统一形状，前端不用判断对象还是字符串。
- 标签列表返回的是 `slug`，但过滤用的是 `tags__name__in`。英文标签 `Django` 的 slug 是 `django`，侧栏点进去传 `?tag=django`，而 `__in` 是大小写敏感的，实测查不到；文章卡片用的是标签名，所以从卡片点进去正常。这是当前实现的一个真实缺陷，修复方向是后端先按 slug 找到 Tag，再用 `tags=tag` 过滤，或改成 `name__iexact`。
- `TagInput` 在失焦时也会把草稿加进去，用户点保存前没回车也不会丢标签。
- 标签没有独立的创建接口，只能在发文章时顺带产生；删除文章后孤立标签仍留在 `taggit` 表里，侧栏可能出现 0 篇文章的标签。
- 标签数量上限 10 是前端限制，后端没有强制；直接调 API 可以传更多。

## 小结

栏目和标签把文章组织起来了，但列表还缺视觉入口。下一章处理封面图，让文章卡片有图可看。
