# 34. 锚点

## 本章目标

- 让 Markdown 标题自动带唯一 `id`。
- 从正文提取目录，返回 `level/text/anchor`。
- 点击目录平滑滚动，滚动时高亮当前小节。
- 让带 `#anchor` 的链接能直接定位。

## 原教程怎么做

原教程用三种方式演示锚点：在评论容器上拼 `id="comment_elem_{{ comment.id }}"`，通知链接末尾拼 `#comment_elem_...`；用 JavaScript 读取偏移量滚动；以及用模板标签生成目录。核心都是手写 `id` 再让浏览器跳转。

## 本实作怎么做

标题 `id` 不手写，交给 Python-Markdown 的 `toc` 扩展。`backend/blog/utils.py` 的渲染配置是：

```python
MD_EXTENSIONS = ["fenced_code", "codehilite", "toc", "tables"]
MD_EXTENSION_CONFIGS = {"toc": {"permalink": False, "toc_depth": "1-6"}}
```

`markdown.markdown()` 生成 `<h2 id="...">`，随后 `bleach.clean()` 的白名单允许 `id` 属性，所以锚点不会被洗掉。`extract_toc()` 再跑一次 Markdown，读取 `md.toc_tokens`，递归拍平成：

```python
{"level": 2, "text": "本章目标", "anchor": "_1"}
```

中文标题要特别注意：Python-Markdown 默认的 `slugify` 会把非 ASCII 字符过滤掉，所以 `## 本章目标` 得到的不是“本章目标”，而是 `_1`；`### 中文小节` 得到 `_2`。我用实际代码验证过：

```python
extract_toc('## 本章目标\n\n### 中文小节')
# [{'level': 2, 'text': '本章目标', 'anchor': '_1'}, {'level': 3, 'text': '中文小节', 'anchor': '_2'}]
```

锚点仍然唯一、可用，但不可读，也不能从标题猜出来。序列化器 `ArticleSerializer.get_toc()` 把它放进详情响应，前端不需要自己解析 HTML。

为什么不交给前端从 `body_html` 里抓标题？因为后端已经渲染过一次 Markdown，标题 `id` 以那次为准；前端再解析一遍，遇到代码块里的 `#` 或重复标题，结果可能对不上。目录和正文必须来自同一份渲染结果。

`TocRail.vue` 负责两件事。点击时：

```js
const el = document.getElementById(anchor)
el.scrollIntoView({ behavior: 'smooth', block: 'start' })
```

滚动高亮用 `IntersectionObserver`，只观察 `.article-body .prose` 下的 `h1` 到 `h4`，`rootMargin` 设为 `-90px 0px -70% 0px`，让“刚进入顶栏下方”的标题成为当前项。

路由层也支持 hash。`router/index.js` 的 `scrollBehavior` 遇到 `to.hash` 时返回 `{ el: to.hash, top: 96, behavior: 'smooth' }`，所以从站内其他页面跳 `#_1` 也能定位。

CSS 里给标题加了 `scroll-margin-top: calc(var(--header-h) + 24px)`，否则固定顶栏会盖住目标标题的第一行。这个值要和 `--header-h` 一起改；顶栏高度变了，偏移不跟着变，锚点就会偏。

`TocRail` 在 `onBeforeUnmount` 里调用 `observer.disconnect()`。文章页切换 slug 时组件会重建，不断开旧观察器会一直持有已卸载的 DOM，滚动时白跑回调。

## 在 MacBook 上操作

```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py runserver 127.0.0.1:8000
```

打开一篇文章，点右侧目录的任意一项，地址栏会变成 `#_1` 这类锚点，页面平滑滚动。刷新页面后仍应停在那个位置。

## 验证

请求详情接口，检查 `toc`：

```bash
curl -s http://127.0.0.1:8000/api/articles/hello-world/ | python3 -m json.tool | head -40
```

实际字段里应能看到 `"toc": [{"level": 1, "text": "...", "anchor": "_1"}]` 这样的结构。如果文章没有标题，`toc` 是空数组。

自动化测试在 `blog/tests.py` 的 `test_detail_renders_markdown_toc_and_increments_views`：一篇带一级、二级标题的文章，断言 `len(data["toc"]) == 2`，并且第一个 `anchor` 非空，标题文字是“大标题”。同一篇还带代码块和表格，用来确认 `codehilite` 与 `tables` 扩展没有把目录弄乱。跑全量测试时这一条会一起执行。

## 踩坑与差异

第一个坑是锚点不可读。中文标题会变成 `_1`、`_2` 这种序号，链接分享出去看不出指向哪一节。要改成中文锚点，需要在 `MD_EXTENSION_CONFIGS["toc"]` 里传 `slugify` 函数，保留 CJK 字符。当前没做，因为目录点击只在页内使用，序号够用。

第二个坑是 `id` 重复。两个同名标题理论上会撞，但 Python-Markdown 的 `toc` 扩展会去重；如果你在正文里手写 `<div id="...">`，仍可能和生成的 `_1` 撞车。

第三个坑是 `bleach`。只允许标签不够，`id` 必须在 `ALLOWED_ATTRIBUTES` 里；否则标题渲染出来没有 `id`，目录全是死链接。

第四个差异是通知锚点。原教程把通知链接拼到 `#comment_elem_<id>`；本实作的通知只跳到文章页，没有带评论锚点。原因是评论节点当前没有稳定的 `id` 属性输出。要补的话，在 `CommentNode` 根元素加 `:id="'comment-' + comment.id"`，再让通知序列化器返回 `comment_id`，链接拼 `#comment-<id>`。这是可选增强，当前版本未实现。

第五个坑是滚动偏移。只写 `scrollIntoView` 不够，固定顶栏会挡住标题；要么加 `scroll-margin-top`，要么在 JS 里减掉 header 高度。本项目用 CSS 解决，JS 保持简单。

标题、目录、锚点三件事打通后，长文章才真正可读。下一章处理第三方登录：这部分本实作没有上线，我会把原因和可选方案写清楚。
