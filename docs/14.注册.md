# 14. 注册

## 本章目标
- 用 `RegisterSerializer` 校验用户名、邮箱和两次密码。
- 注册成功后自动登录并返回用户对象。
- 让 `RegisterView` 与后端字段一一对应。
- 理解 `Profile` 信号在注册链路里的作用。

## 原教程怎么做
原教程写 `UserRegisterForm`，继承 `ModelForm`，`fields = ('username', 'email')`，额外覆写 `password`、`password2`，在 `clean_password2()` 里比较两次密码；视图 `save(commit=False)` 后 `set_password()`，再 `login()` 并跳回列表。

## 本实作怎么做
注册序列化器在 `backend/accounts/serializers.py`：
```python
class RegisterSerializer(serializers.Serializer):
    username = serializers.CharField(max_length=150)
    email = serializers.EmailField(required=False, allow_blank=True)
    password1 = serializers.CharField(write_only=True)
    password2 = serializers.CharField(write_only=True)

    def validate_username(self, value):
        if User.objects.filter(username__iexact=value).exists():
            raise serializers.ValidationError("用户名已存在。")
        return value

    def validate(self, attrs):
        if attrs["password1"] != attrs["password2"]:
            raise serializers.ValidationError({"password2": "两次输入的密码不一致。"})
        validate_password(attrs["password1"])
        return attrs

    def create(self, validated_data):
        return User.objects.create_user(...)
```
`validate_password` 会跑 Django 的四条内置规则：太像用户名、太短、太常见、纯数字。用户名查重用 `iexact`，`Alice` 和 `alice` 视为重复。

`RegisterView` 保存后直接 `login(request, user)`，返回 201 和 `{"user": ...}`；前端 `RegisterView.vue` 的字段名就是 `username`、`email`、`password1`、`password2`，提交后把用户写进 Pinia 并跳首页。`accounts/signals.py` 监听 `post_save`，新用户创建时自动 `Profile.objects.get_or_create`，所以注册返回的 `profile` 不会是 `null`。

注册没有单独的事务包住 `create_user` 和 `login`；如果登录步骤异常，用户可能已创建但没建立会话，重新登录即可。密码由 `create_user` 哈希，不要用 `User(...)` 直接赋明文。

## 在 MacBook 上操作
打开 <http://127.0.0.1:5173/register>，填用户名、可选邮箱、两次密码，点“创建账号”。接口调试：
```bash
curl -s -c /tmp/blog-cookies.txt http://127.0.0.1:8000/api/auth/csrf/
curl -s -b /tmp/blog-cookies.txt -H "X-CSRFToken: <cookie里的值>" \
  -H "Content-Type: application/json" \
  -d '{"username":"newbie","email":"newbie@example.com","password1":"S3cure!Passw0rd","password2":"S3cure!Passw0rd"}' \
  http://127.0.0.1:8000/api/auth/register/
```
返回 201 时响应里有 `user.username`、`user.profile`，并且已经建立会话。

前端的 `guestOnly` 守卫让已登录用户访问 `/register` 时回首页，避免重复注册；表单字段名和后端完全一致，错误信息由 `apiError` 把 `password2` 映射成“确认密码”。注册页不要求邮箱，但填了会存进 `User.email`，后面重置密码会用到。

## 验证
注册成功后首页右上角直接显示用户名，说明自动登录生效；`/api/auth/me/` 能返回新用户；后台或 shell 里 `Profile.objects.filter(user__username="newbie")` 有一条记录。两次密码不一致返回 400 且错误在 `password2`；用户名重复返回 400；弱密码被 `validate_password` 拒绝。`backend/accounts/tests.py` 的 `test_register_creates_profile_and_returns_user` 和 `test_register_rejects_mismatched_passwords` 覆盖了这些情况。

还要检查用户名大小写：注册 `Alice` 后再注册 `alice` 应返回 400；这是 `iexact` 的效果。

## 踩坑与差异
- 原教程字段叫 `password`/`password2`；本实作统一成 `password1`/`password2`，前端表单必须同名，否则后端收不到。
- 邮箱是可选字段，允许空字符串；原教程的 `ModelForm` 里 email 也是可空，但这里明确写了 `allow_blank=True`。
- 密码校验不只比较两次输入，还会跑 Django 的密码验证器；测试账号别用纯数字。
- `Profile` 不是注册视图手动建的，而是信号建的；如果你在 shell 里直接 `User.objects.create()`，同样会有 Profile。
- 注册成功会直接建立 session，不需要再调登录接口；如果你希望注册后手动登录，把 `RegisterView` 里的 `login()` 去掉并只返回用户。
- `RegisterSerializer` 是普通 `Serializer`，不是 `ModelSerializer`；字段和校验都手写，改字段时要同时改前端和测试。
- `UserSerializer` 会 `get_or_create` Profile，所以即使信号被临时断开，注册返回的 `profile` 也不会是 `null`。
- 注册页的 `guestOnly` 只在有用户时拦截；匿名访问正常显示表单。
- 密码验证器的错误信息会按字段返回，前端用 `apiError` 拼接。

注册接口不需要登录，`AllowAny` 是显式写的，不要依赖全局默认权限；以后改默认权限也不会把注册关掉。

注册接口只接受 POST，GET 会 405；不要用浏览器地址栏触发。

## 小结
用户能注册、能登录，最后一章处理注销账号：验证密码、退出会话、级联删数据。
