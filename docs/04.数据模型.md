# 04. 数据模型

## 本章目标
- 定义栏目、文章、点赞三个核心模型。
- 让 `Article` 自动生成唯一 slug，并在保存时缓存渲染后的 HTML。
- 定义两级评论、用户资料和通知模型。
- 理解外键删除策略与唯一约束的作用。

## 原教程怎么做
原教程只写了一个 `ArticlePost`：作者外键、标题、正文、创建时间、更新时间，`Meta.ordering` 按创建时间倒序，`__str__` 返回标题。创建时间用 `default=timezone.now`，更新用 `auto_now=True`。

## 本实作怎么做
文章相关模型在 `backend/blog/models.py`。`ArticleColumn` 是栏目，`Article` 是文章，`ArticleLike` 记录谁点了赞：
```python
class Article(models.Model):
    author = models.ForeignKey(User, on_delete=models.CASCADE, related_name="articles")
    title = models.CharField(max_length=200)
    slug = models.SlugField(max_length=220, unique=True, blank=True)
    body = models.TextField()
    body_html = models.TextField(blank=True, default="")
    cover = models.ImageField(upload_to="covers/", blank=True, null=True)
    column = models.ForeignKey(ArticleColumn, on_delete=models.SET_NULL, null=True, blank=True)
    tags = TaggableManager(blank=True)
    total_views = models.PositiveIntegerField(default=0)
    likes = models.PositiveIntegerField(default=0)
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)
```
`save()` 里先补 slug，再调用 `render_markdown(self.body)` 写入 `body_html`：
```python
def save(self, *args, **kwargs):
    if not self.slug:
        self.slug = self._unique_slug()
    self.body_html = render_markdown(self.body)
    super().save(*args, **kwargs)
```
`_unique_slug()` 用 `slugify(..., allow_unicode=True)`，重名时追加 `-2`、`-3`，所以中文标题也能得到可读 slug。`ArticleLike` 用 `UniqueConstraint(fields=["article", "user"])` 保证同一用户对同一文章只有一条点赞记录，后面点赞接口才能做成幂等切换。

评论在 `backend/comments/models.py`，`parent` 指向自身，`related_name="replies"`，删除父评论会级联删除回复；`active` 用来软删除。用户资料在 `backend/accounts/models.py`，`Profile` 与 `User` 是一对一，字段是 `phone`、`bio`、`avatar`。通知在 `backend/notices/models.py`，字段有 `recipient`、`actor`、`verb`、`target_article`、`target_comment`、`unread`。

`ArticleColumn` 只有 `title`、`slug`、`created`，`Meta.ordering = ["title"]`，后台和侧栏都按标题排。`Article.Meta.ordering = ["-created"]` 保证默认列表最新在前；`cover` 用 `upload_to="covers/"`，文件落到 `MEDIA_ROOT/covers/`；`tags` 由 `TaggableManager` 管理，序列化器负责转成字符串数组。`ArticleLike` 除了唯一约束，还给了 `related_name="article_likes"`，详情接口判断 `liked` 时直接查这个反向关系。

## 在 MacBook 上操作
模型写完后生成并应用迁移：
```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py makemigrations
python manage.py migrate
python manage.py showmigrations --list
```
当前仓库里 `blog`、`comments`、`accounts`、`notices` 的 `0001_initial` 都显示 `[X]`。如果你改了字段，先 `makemigrations` 再 `migrate`，不要手改 `db.sqlite3`。

生成迁移时，Django 会把模型差异写进 `backend/blog/migrations/0001_initial.py` 这类文件；这些文件要提交到仓库，部署时才能复现表结构。`makemigrations` 只写文件，`migrate` 才动数据库。当前 `db.sqlite3` 已经应用过四个 app 的首个迁移，所以直接启动不会报 `no such table`。

## 验证
在 shell 里取一篇文章，确认 slug 和 HTML 都自动生成：
```bash
python manage.py shell -c "from blog.models import Article; a=Article.objects.first(); print(a.slug); print(bool(a.body_html))"
```
有数据时应打印非空 slug 和 `True`。再检查 `ArticleLike`：对同一文章、同一用户插入第二条会触发 `IntegrityError`，`backend/blog/tests.py` 的 `test_like_unique_constraint` 就是验证这一点。

验证 slug 唯一性时，可以连续创建两篇同名文章，第二篇应得到 `hello-world-2` 之类的后缀；`backend/blog/tests.py` 的 `test_slug_auto_generated_and_unique` 和 `test_slug_supports_chinese_titles` 已经覆盖。验证评论树时，先建一条根评论，再建一条 `parent=根评论` 的回复，`根.replies.count()` 应为 1；回复的回复在视图里会被归到根评论下，保持两级。

## 踩坑与差异
- 原教程模型叫 `ArticlePost`，本实作叫 `Article`，字段多了 `slug`、`body_html`、`cover`、`column`、`tags`、`total_views`、`likes`。
- 原教程创建时间用 `default=timezone.now`，这里用 `auto_now_add=True`；更新时间用 `auto_now=True`。
- `column` 用 `SET_NULL`，栏目删掉文章还在；`author` 用 `CASCADE`，用户删掉文章一起删。
- 标签用 `django-taggit`，不是自己写多对多表。
- `body_html` 是冗余字段，目的是读详情时不再渲染 Markdown；改正文后必须走 `save()`，用 `QuerySet.update(body=...)` 不会刷新它。
- `ArticleLike.likes` 计数和 `ArticleLike` 表是两套数据，点赞接口必须同时维护，不能只改计数。
- `Comment.active` 是软删除标记，列表和评论树都只取 `active=True`，物理删除只发生在文章或用户级联时。
- `Article.save()` 会覆盖 `body_html`，后台批量导入或脚本改正文时也要走模型保存，不要直接用 SQL 写表。

模型层是后面所有接口的地基，字段类型和删除策略一旦定错，改起来要连带迁移和前端。

## 小结
数据层有了文章、评论、资料和通知，下一章先做一个最小 API 和后台入口，确认数据能被取出来。
