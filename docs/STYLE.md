# 教程写作规范（供写作代理使用）

## 读者与语气
- 读者：会一点 Python、想在 macOS 上做一个能上线的个人博客。
- 第一人称，像在记录自己踩过的坑；不写“本文将介绍”这类空话。
- 每个结论尽量给出可执行的命令或文件路径。

## 每章结构
1. `# 章节号. 标题`
2. `## 本章目标`：3–5 条。
3. `## 原教程怎么做`：两三句话概括原章节做法。
4. `## 本实作怎么做`：讲清架构位置（Django app / DRF / Vue 组件 / nginx），给关键代码片段与文件路径。
5. `## 在 MacBook 上操作`：实际命令与预期输出；不要编造输出。
6. `## 验证`：如何确认这一步真的生效（curl、测试、页面操作）。
7. `## 踩坑与差异`：真实问题；没有就写“本章没有遇到额外问题”。
8. `## 小结`：下一章衔接。

## 事实来源
- 原文章节：`source/md/<原名>.md`（只读）。
- 实际代码：`backend/`、`frontend/`（只读，不要改）。
- 差异记录：`docs/DIFFERENCES.md`。
- 规格：`SPEC.md`。
- 不确定的实现细节，先读代码再写；读不到就明确写“未实现/可选”，不要编。

## 禁止
- 不要逐段复制原教程文字。
- 不要写没有验证过的命令输出。
- 不要承诺未实现的功能。
- 不要修改 `backend/`、`frontend/`，只写指定的 `docs/*.md`。
