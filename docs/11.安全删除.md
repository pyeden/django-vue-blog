# 11. 安全删除

## 本章目标
- 用对象级权限限制删除操作。
- 让作者和管理员才能删除文章。
- 在前端加二次确认，避免误点。
- 理解删除文章时评论、点赞的级联行为。

## 原教程怎么做
原教程写 `article_delete(request, id)`，用 `ArticlePost.objects.get(id=id)` 取出文章后直接 `.delete()`，再 `redirect` 回列表；详情页放一个“删除文章”链接。它自己也承认这样任何人都能删，后面才补用户权限，并用 layer 弹窗做确认。

## 本实作怎么做
权限在 `backend/blog/views.py` 的 `IsAuthorOrStaff`：
```python
class IsAuthorOrStaff(permissions.BasePermission):
    message = "只有作者本人或管理员可以执行此操作。"

    def has_object_permission(self, request, view, obj):
        if request.method in permissions.SAFE_METHODS:
            return True
        if not request.user or not request.user.is_authenticated:
            return False
        return request.user.is_staff or obj.author_id == request.user.id
```
`ArticleViewSet` 把它和 `IsAuthenticatedOrReadOnly` 一起挂在 `permission_classes` 上：读请求放行，写请求必须登录且通过对象权限。DELETE `/api/articles/<slug>/` 命中 `destroy`，删除成功返回 204。

前端 `frontend/src/views/ArticleDetailView.vue` 只在 `canManage` 为真时显示删除按钮：
```js
const isAuthor = computed(() => auth.isAuthenticated && auth.username === article.value?.author?.username)
const canManage = computed(() => auth.isStaff || isAuthor.value)
```
点击后先 `window.confirm`：
```js
async function removeArticle() {
  if (!window.confirm('确定删除这篇文章吗？删除后不可恢复。')) return
  try {
    await deleteArticle(slug.value)
    toast.success('文章已删除')
    router.push({ name: 'home' })
  } catch (err) {
    toast.error(apiError(err, '删除失败'))
  }
}
```
确认框是浏览器原生能力，不引入 layer 或额外弹窗库；样式不花哨，但行为明确。

## 在 MacBook 上操作
用作者账号登录，打开自己的文章详情，点“删除”，在确认框里点确定。页面应提示“文章已删除”并回到首页。直接调接口时要带 CSRF：
```bash
curl -s -b /tmp/blog-cookies.txt -X DELETE \
  -H "X-CSRFToken: <cookie里的值>" \
  http://127.0.0.1:8000/api/articles/<slug>/
```
成功时 HTTP 状态是 204，响应体为空。

## 验证
删除后文章详情返回 404，首页列表少一篇。用另一个普通账号请求同一 DELETE 应返回 403；未登录请求返回 401/403。`backend/blog/tests.py` 的 `test_author_can_delete` 和 `test_non_author_cannot_update_or_delete` 分别覆盖作者删除与非作者拦截。评论和点赞通过外键 `CASCADE` 一起消失。

## 踩坑与差异
- 原教程先做出“谁都能删”的版本，再补权限；本实作一开始就用对象权限，避免留下不安全的中间态。
- 原教程用 layer 弹窗；本实作用 `window.confirm`，少一个前端依赖，确认文案直接把“不可恢复”说清楚。
- DELETE 成功是 204，没有 JSON body，axios 的 `data` 会是空字符串，不要按普通 JSON 解析。
- 删除按钮只对作者和 staff 显示，但真正的拦截在服务端；不要只靠前端隐藏按钮。除此之外本章没有遇到额外问题。
