# 09. Markdown 渲染

## 本章目标
- 在服务端把 Markdown 渲染成 HTML。
- 用 bleach 白名单阻止脚本和事件属性。
- 从 Markdown 提取目录，并生成纯文本摘要。
- 前端二次清洗，预览与最终渲染分开。

## 原教程怎么做
原教程在 `article_detail()` 里调用 `markdown.markdown(article.body, extensions=['markdown.extensions.extra', 'markdown.extensions.codehilite'])`，模板里用 `{{ article.body|safe }}` 输出；再用 Pygments 生成 `monokai.css` 给代码块上色。

## 本实作怎么做
渲染逻辑集中在 `backend/blog/utils.py`，模型保存时调用，不在视图里临时处理：
```python
MD_EXTENSIONS = ["fenced_code", "codehilite", "toc", "tables"]
MD_EXTENSION_CONFIGS = {
    "codehilite": {"css_class": "codehilite", "guess_lang": False, "linenums": False},
    "toc": {"permalink": False, "toc_depth": "1-6"},
}

def render_markdown(text: str) -> str:
    html = markdown.markdown(
        text, extensions=MD_EXTENSIONS, extension_configs=MD_EXTENSION_CONFIGS
    )
    return bleach.clean(
        html,
        tags=ALLOWED_TAGS,
        attributes=ALLOWED_ATTRIBUTES,
        protocols=ALLOWED_PROTOCOLS,
        strip=True,
    )
```
`ALLOWED_TAGS` 只保留标题、段落、列表、链接、图片、表格、`pre/code` 等；`ALLOWED_ATTRIBUTES` 只允许 `class`、`id`、`href`、`src`、`alt` 这类必要属性；协议白名单是 `http`、`https`、`mailto`。`script`、`style`、`onclick` 都会被清掉。`Article.save()` 把结果写进 `body_html`，所以详情接口不需要每次重新渲染。

`extract_toc(text)` 复用同一个 Markdown 实例，递归读取 `toc_tokens`，返回扁平列表：
```python
{"level": token.get("level", 1), "text": token.get("name", ""), "anchor": token.get("id", "")}
```
`make_excerpt(text)` 先去掉代码块、图片、链接语法和标题符号，再截到 120 字，给列表卡片用。

前端 `frontend/src/components/MarkdownBody.vue` 不直接 `v-html` 原始字符串，而是先过 `sanitizeHtml`（DOMPurify）。编辑器里的“实时预览”走 `frontend/src/utils/markdown.js` 的 `marked.parse`，只用于写作时看效果，最终页面仍以服务端 `body_html` 为准。

bleach 的白名单是“只保留列出的”，不是“过滤几个危险标签”。`ALLOWED_TAGS` 没有 `iframe`、`form`、`style`，`ALLOWED_ATTRIBUTES` 也没有 `on*` 事件；`strip=True` 表示不在白名单的标签直接去掉标签本身，内容保留。`codehilite` 的 `css_class` 固定为 `codehilite`，前端样式表里对应的 `.prose pre .k` 等规则才能命中。

## 在 MacBook 上操作
```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py shell -c "from blog.utils import render_markdown; print(render_markdown('# 标题\n\n**粗体**'))"
```
我实际得到：
```html
<h1 id="_1">标题</h1>
<p><strong>粗体</strong></p>
```
注意中文标题的锚点是 `_1`，不是汉字本身；目录链接要用接口返回的 `anchor`，不要自己拼。

`extract_toc` 走的是 Python-Markdown 的 `toc_tokens`，不是正则扫 `#`。嵌套标题会递归展开，所以 `h1 > h2 > h3` 的顺序和正文一致。`make_excerpt` 会先把代码块整段删掉，再把链接语法还原成文字，最后压缩空白；它不渲染 HTML，只生成纯文本，避免列表卡片里出现标签。

## 验证
请求任意文章详情，`body_html` 里应出现 `codehilite` 类和代码高亮所需的 class；`toc` 是与正文标题顺序一致的数组。写一段 `<script>alert(1)</script>` 和带 `onclick` 的标签再保存，详情里不会出现 `<script` 和 `onclick`。`backend/blog/tests.py` 的 `test_markdown_xss_is_sanitized` 覆盖了这一点。

验证 XSS 时，除了 `<script>`，还要试 `<img src=x onerror=alert(1)>` 和 `[链接](javascript:alert(1))`；前者的事件属性会被 bleach 去掉，后者的 `javascript:` 协议不在白名单，链接会被清成普通文本。前端 `MarkdownBody` 再过一遍 DOMPurify，是双保险，不是重复劳动。

## 踩坑与差异
- 原教程用 `|safe` 直接输出，等于信任作者输入；本实作在保存时就做 bleach 清洗，前端再加一层 DOMPurify。
- 原教程用 Pygments 生成整份主题文件；本实作只保留 `codehilite` 的 class，颜色写在 `main.css` 的 `.prose pre .k` 等规则里。
- 中文标题的锚点由 Python-Markdown 生成，可能是 `_1`、`_2`，不要假设它等于标题文字。
- 编辑器预览用 `marked`，服务端用 Python-Markdown，两者对极端语法可能有细微差异；以发布后的 `body_html` 为准。
- 编辑器预览用 `marked`，服务端用 Python-Markdown；两边对表格对齐、脚注等扩展支持不同，预览好看不代表发布后完全一样。
- `highlight.js` 的 CSS 只影响前端预览和代码块底色，服务端 `codehilite` 的 token class 由 `main.css` 里的规则上色。
- 不要把用户输入的 HTML 直接塞进 `v-html`，即使后端已经清洗过，前端仍应走 `sanitizeHtml`。

## 小结
Markdown 能安全地变成 HTML，也有了目录和摘要，下一章把写作表单、标签、栏目和封面上传接起来。
