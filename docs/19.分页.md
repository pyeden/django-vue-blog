# 19. 分页

## 本章目标

- 理解为什么文章列表必须分页：减少响应体积、减少数据库一次取出的行数、让页面有稳定节奏。
- 用 DRF 的 `PageNumberPagination` 定义全站默认分页，而不是每个视图各写一套。
- 让前端把 `count/next/previous` 转成页码条，并在筛选条件变化时回到第一页。
- 知道当前分页的边界行为：页码越界时 API 返回 404，前端只生成合法页码。

## 原教程怎么做

原教程用 Django 自带的 `Paginator`，在 shell 里演示 `count`、`num_pages`、`page_range`、`has_next` 等方法，然后在列表视图里取 `page = request.GET.get('page')`，调用 `paginator.get_page(page)`，模板里渲染上一页、下一页和页码。它还会讲每页放几条、页码太多时怎么只显示附近几页。

## 本实作怎么做

分页器在 `backend/blog/pagination.py`：

```python
class DefaultPagination(PageNumberPagination):
    page_size = 6
    page_size_query_param = "page_size"
    max_page_size = 50
```

`backend/config/settings.py` 把它设为全局默认，并保留 `PAGE_SIZE=6`：

```python
"DEFAULT_PAGINATION_CLASS": "blog.pagination.DefaultPagination",
"PAGE_SIZE": 6,
```

这样 `ArticleViewSet` 不用写任何分页代码，列表接口自动返回 `count`、`next`、`previous`、`results`。`page_size` 查询参数允许前端临时改每页数量，但不能超过 50，避免有人用 `page_size=100000` 拖垮数据库。

前端 `frontend/src/components/ArticleFeed.vue` 固定请求 `page_size=6`，用返回的 `count` 算总页数：

```js
const data = await listArticles({ page: page.value, page_size: 6, ...props.filters })
totalPages.value = Math.max(1, Math.ceil(data.count / 6))
```

`PaginationBar.vue` 只负责显示：总页数不超过 7 时全部列出，超过时保留第一页、最后一页、当前页和左右各一页，其余用省略号折叠。它通过 `update:page` 事件把新页码交给父组件，自己不直接发请求。

筛选条件变化时，`ArticleFeed` 监听 `filterKey`，先把 `page` 重置为 1 再加载。否则从第 5 页切到某个只有一页的栏目，会请求一个不存在的页码。

## 在 MacBook 上操作

```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py runserver 127.0.0.1:8000
```

请求第二页，每页 3 条：

```bash
curl -s 'http://127.0.0.1:8000/api/articles/?page=2&page_size=3'
```

返回体里应能看到 `count`、`next`、`previous` 和 `results`。前端打开首页，底部页码条应能切换，地址栏不会变化，因为页码是组件状态而不是路由参数。

## 验证

- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_list_default_page_size_is_six`：造 8 篇文章，第一页应返回 6 条，`count` 为 8。
- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_list_page_size_override_and_page`：`page_size=3&page=2` 应返回 3 条，并且 `previous` 不为空。
- 手动把 `page_size` 改成 100，返回条数不应超过 50。
- 把 `page` 改成 999，DRF 会返回 404；这是预期行为，不要在前端生成这种页码。

## 踩坑与差异

- 原教程在模板里算页码；这里把“取数”和“显示”分开，API 只给元数据，页码算法在 Vue 组件里。
- `ArticleFeed` 用固定的 6 算总页数，如果以后把 `page_size` 做成用户可选，必须同步改这个除数，否则页码会错。
- DRF 的 `count` 是过滤后的总数，不是当前页条数；页面上“共 N 篇”要用 `count`，不能用 `results.length`。
- 页码越界时 DRF 默认 404，不会自动夹到最后一页。当前前端只发出合法页码，所以不会触发；如果以后支持手输页码，要自己兜底。
- 列表默认按 `-created` 排序，分页才稳定。若按浏览量排序且浏览量相同，顺序可能抖动，需要再加 `-id` 作为次级排序。

页码条不是路由的一部分，刷新页面会回到第一页；这对个人博客可以接受。若希望分享第 N 页，需要把 page 写进 query，并在组件初始化时从路由读取。当前没有做，是为了让筛选、搜索和分页的状态更简单，少一层同步就少一类 bug。

## 小结

分页让列表可控了。下一章给文章加浏览量，并确保自增是数据库层面的原子操作，不会因为并发丢计数。
