# 25. 课间休息

## 本章目标

- 把第 1–24 章的实现按“数据、接口、页面、验证”四层复盘一遍。
- 确认当前哪些功能已经跑通，哪些只是接口存在、前端还没接。
- 用测试和手动冒烟给自己一个阶段结论，而不是凭感觉说“差不多了”。
- 明确后半程的重点：ViewSet、栏目、标签、封面、编辑器、通知、点赞、测试与部署。

## 原教程怎么做

原教程这一章没有新代码，主要是鼓励读者坚持，顺带讨论“要不要现在部署”“接下来学什么”。它提醒：学到一半容易疲，先把已完成的功能跑起来看看，再决定继续补哪块。部署可以晚一点，但不要等到最后才第一次上线。

## 本实作怎么做

前二十四章已经形成一条完整链路：

- 数据层：`accounts.Profile`、`blog.ArticleColumn`、`blog.Article`、`blog.ArticleLike`、`comments.Comment`、`notices.Notification`。
- 接口层：认证、资料、文章 CRUD、点赞、最热、栏目、标签、评论树、通知。
- 页面层：首页、详情、写作、编辑、登录、注册、重置申请、资料、搜索、栏目归档、标签归档、通知、404。
- 基础设施：Session + CSRF、DRF 分页、Markdown 渲染与清洗、媒体目录、日志。

这时最值得做的不是继续堆功能，而是把已有路径走一遍：注册一个新账号，发一篇带标题层级的文章，改一次、删一次，再发评论、回复、点赞，最后看通知。走完这一圈，你会比读十篇“最佳实践”更清楚项目缺什么。

## 在 MacBook 上操作

```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py test
python manage.py check
```

测试当前是 50 个，全部通过；`check` 应报告 no issues。前端另开终端：

```bash
cd ~/work/django-vue-blog/frontend
npm run dev
```

按上面的冒烟顺序在浏览器里操作。遇到 403，先看是不是没带 CSRF；遇到 401，先看会话是否过期；遇到图片 404，先看 `media/` 路径和开发服务器的静态路由。

## 验证

- 后端测试全绿，且没有跳过项。
- `python manage.py makemigrations --check --dry-run` 不应提示缺少迁移。
- 首页能分页，搜索能出结果，最热能排序，详情能显示目录。
- 评论树最多两层，回复的回复会挂到根评论。
- 未登录不能发文、评论、点赞；非作者不能改删别人的文章。

## 踩坑与差异

- 原教程在模板体系里推进，页面和视图是一体的；这里前后端分开，任何一个功能都要同时检查 API 形状和组件状态，漏一边就会“接口对了但页面不动”。
- 前半程最容易积累的是迁移和环境问题：SQLite 文件、`media/`、虚拟环境路径。换机器前先确认这些不在 Git 里。
- 测试通过不等于页面通过；反过来说，页面能点也不等于权限正确。两边都要看。
- 当前重置密码只有申请页，确认页未实现；搜索没有高亮；浏览量没有去重。这些都应该记在待办里，而不是假装完成。

如果你现在就想部署，也可以，但先把 `DEBUG=False` 下的静态文件、媒体文件和 CSRF 来源过一遍。更稳的做法是等栏目、标签、封面和编辑器都完成后再统一部署，避免每加一个功能就改一次 nginx。阶段复盘的价值在于知道自己在哪，而不是急着抵达终点。
