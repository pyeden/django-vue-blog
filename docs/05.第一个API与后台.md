# 05. 第一个 API 与后台

## 本章目标
- 用 `JsonResponse` 提供 `/api/health/`。
- 把文章、栏目、点赞、评论、通知注册进 Django admin。
- 配置 DRF 的 Session 认证与默认分页。
- 创建超级用户并登录后台。

## 原教程怎么做
原教程在 `article/views.py` 写一个 `article_list` 函数，直接 `return HttpResponse("Hello World!")`，再在 `article/urls.py` 配一条 `article-list/`。随后用 `createsuperuser` 建管理员，并在 `admin.py` 里 `admin.site.register(ArticlePost)`，靠后台录入测试数据。

## 本实作怎么做
最小的“能通”接口是健康检查。`backend/config/urls.py` 里没有单独建 app，直接写函数：
```python
def health(request):
    return JsonResponse({"status": "ok"})

urlpatterns = [
    path("admin/", admin.site.urls),
    path("api/health/", health, name="health"),
    ...
]
```
它不碰数据库，适合给前端、gunicorn 或 nginx 做存活探测。

后台注册在 `backend/blog/admin.py`：`ArticleColumn`、`Article`、`ArticleLike` 都用 `@admin.register`。`ArticleAdmin` 把 `body_html`、`total_views`、`likes` 设为只读，并提供栏目、时间、作者筛选：
```python
@admin.register(Article)
class ArticleAdmin(admin.ModelAdmin):
    list_display = ("title", "author", "column", "likes", "total_views", "created")
    list_filter = ("column", "created", "author")
    search_fields = ("title", "body", "author__username")
    readonly_fields = ("body_html", "total_views", "likes", "created", "updated")
```
评论和通知分别在 `backend/comments/admin.py`、`backend/notices/admin.py` 注册，后台能看到 `active` 与 `unread`。

DRF 的全局配置在 `backend/config/settings.py`：认证用 `SessionAuthentication`，默认权限 `AllowAny`，分页类指向 `blog.pagination.DefaultPagination`，每页 6 条。默认权限放开是为了让首页和详情页匿名可读，写操作再由各视图单独收紧。

健康检查放在根路由而不是某个 app，是因为它不属于业务；以后加负载均衡或容器探针，直接请求这个地址即可。后台的 `ArticleAdmin` 还设置了 `date_hierarchy = "created"`，文章多时能按日期钻取；`prepopulated_fields` 让 slug 随标题自动填充，但真正保存时模型还会再校验唯一性。DRF 的 `DEFAULT_FILTER_BACKENDS` 配了 `SearchFilter` 和 `OrderingFilter`，所以文章列表不用自己解析查询参数。

## 在 MacBook 上操作
```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```
另开终端请求健康检查：
```bash
curl -s http://127.0.0.1:8000/api/health/
```
我在本地用 Django 测试客户端请求同一路径，得到状态 200、响应体 `{"status": "ok"}`；未登录请求 `/admin/` 得到 302，跳到 `/admin/login/?next=/admin/`。浏览器打开 <http://127.0.0.1:8000/admin/>，用刚建的账号登录，就能在 `Articles` 里新增文章。

`createsuperuser` 会依次提示 `Username`、`Email address`、`Password`，密码输入时不回显；它要求至少 8 位且不能太常见。管理员账号只用于后台和应急，不要把 `is_superuser` 当成普通作者账号。启动开发服务器后，`/admin/` 的静态文件由 Django 自己服务，生产环境则要 `collectstatic` 后交给 nginx。

## 验证
健康检查返回 200；后台能登录并看到 `Article columns`、`Articles`、`Article likes`、`Comments`、`Notifications` 五组模型；在后台新增一篇文章后，`python manage.py shell -c "from blog.models import Article; print(Article.objects.count())"` 的数量会增加。后台保存文章时 `body_html` 会自动生成，说明模型里的 `save()` 已生效。

后台新增文章时，`body` 填 Markdown 原文，保存后 `body_html` 会由模型自动生成；如果后台表单里没看到 `body_html`，那是因为它被设为只读，不是漏字段。健康检查返回的 `{"status": "ok"}` 是固定字符串，不查数据库，所以数据库挂了它仍可能返回 200；要做完整探活，应另加一个查库的接口。

## 踩坑与差异
- 原教程返回纯文本 `HttpResponse`，这里返回 JSON，前端才能直接解析。
- 原教程后台只注册文章；这里文章、栏目、点赞、评论、通知都注册，调试评论树和通知时不用写临时脚本。
- DRF 默认 `AllowAny` 只适合读接口。新建、修改、删除在 ViewSet 上另加 `IsAuthenticatedOrReadOnly` 和对象权限，不要以为全局配置已经安全。
- 开发环境 CORS 与 CSRF 只放行 `http://localhost:5173` 和 `http://127.0.0.1:5173`，换端口要改环境变量。
- 原教程的 `HttpResponse` 不会设置 JSON Content-Type；`JsonResponse` 会，前端 axios 才能直接拿到对象。
- `ALLOWED_HOSTS` 在 `DEBUG=True` 时默认 `["*"]`，生产必须显式配置，否则 nginx 转发会 400。
- 后台路径是 `/admin/`，不是 `/api/admin/`；API 统一前缀只作用于业务接口。

## 小结
后台能录数据、健康检查能返回 JSON，下一步把文章列表做成真正的 API，并让 Vue 首页消费它。
