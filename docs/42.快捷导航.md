# 42. 快捷导航

## 本章目标
- 让读者在文章之间快速移动。
- 保留原教程“文章快捷导航”的体验。

## 原教程怎么做
原教程在详情页底部加上一篇/下一篇，并在导航栏放栏目和排序入口，靠视图传 `prev_article` / `next_article`。

## 本实作怎么做
本实作没有做“上一篇/下一篇”接口，而是用三个更轻的入口替代：

1. 详情页右侧的 `TocRail`：长文内跳转。
2. 侧栏“最热文章”：横向发现。
3. 栏目/标签归档：按主题浏览。

如果要做上下篇，最省事的方式是在 `ArticleSerializer` 里加两个 `SerializerMethodField`：

```python
def get_prev(self, obj):
    return Article.objects.filter(created__lt=obj.created).order_by("-created").values("title", "slug").first()
```

再在 `ArticleDetailView` 底部渲染两个链接即可。注意按 `created` 排序时要处理同一时间创建的文章。

## 在 MacBook 上操作
当前不需要迁移；只改序列化器和前端组件。

## 验证
- 目录点击能滚动到对应标题。
- 最热文章链接能打开详情。
- 归档页分页正常。

## 踩坑与差异
“快捷导航”不是越多越好。详情页已经有目录和评论，再塞上下篇会让底部过重；本实作选择先保证阅读动线清晰。

## 小结
导航的目标是减少迷路，不是增加按钮。
