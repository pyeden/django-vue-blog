# 26. ViewSet

## 本章目标

- 理解类视图解决的核心问题：把“按 HTTP 方法分派”和“重复的查询逻辑”收进一个类。
- 用 `ModelViewSet` 一次得到列表、详情、创建、更新、删除五个动作。
- 用 `SimpleRouter` 自动生成 URL，并知道 `lookup_field="slug"` 改变了什么。
- 看懂 `@action` 如何把点赞、封面、最热挂到同一资源下。

## 原教程怎么做

原教程从函数视图讲到类视图，再讲 Django 的通用视图：`ListView` 负责列表，`DetailView` 负责详情，混入类（mixin）负责“只允许作者编辑”之类的横切逻辑。它还会演示动态过滤和额外上下文，说明类视图不是把函数写长，而是把可复用的部分拆开。详情页的编辑、删除则通过 `get_object` 和权限判断控制。

## 本实作怎么做

核心在 `backend/blog/views.py`：

```python
class ArticleViewSet(viewsets.ModelViewSet):
    serializer_class = ArticleSerializer
    lookup_field = "slug"
    lookup_value_regex = r"[^/.]+"
    permission_classes = [permissions.IsAuthenticatedOrReadOnly, IsAuthorOrStaff]
    search_fields = ["title", "body"]
    ordering_fields = ["created", "updated", "total_views", "likes", "title"]
    ordering = ["-created"]
```

`ModelViewSet` 把 `list/retrieve/create/update/partial_update/destroy` 都准备好了。`lookup_field="slug"` 让详情地址变成 `/api/articles/hello-world/`，而不是主键；`lookup_value_regex` 排除点和斜杠，避免中文 slug 或带点的标题把路由切坏。

路由在 `backend/blog/urls.py`：

```python
router = SimpleRouter()
router.register("articles", ArticleViewSet, basename="article")

urlpatterns = [
    path("columns/", ArticleColumnListView.as_view(), name="column-list"),
    path("tags/", TagListView.as_view(), name="tag-list"),
] + router.urls
```

`basename` 必须给，因为 `get_queryset()` 不是固定的 `queryset` 属性，路由器无法自动推断名字。生成的路由包括 `/articles/`、`/articles/{slug}/`，以及自定义动作 `/articles/hot/`、`/articles/{slug}/like/`、`/articles/{slug}/cover/`。

权限分成两层：`IsAuthenticatedOrReadOnly` 保证匿名只能读，`IsAuthorOrStaff` 在对象级判断“作者或管理员才能改删”。`@action` 上的 `permission_classes` 可以覆盖默认值，点赞要求登录，封面要求作者或 staff。

栏目和标签不需要完整 CRUD，所以用 `ListAPIView`，并设 `pagination_class = None`，一次返回全部。类视图不是“越大越好”，只读资源用通用列表视图更轻。

```bash
cd ~/work/django-vue-blog/backend

```

```bash
curl -s http://127.0.0.1:8000/api/articles/ | python3 -m json.tool | head -30
curl -s http://127.0.0.1:8000/api/articles/你的-slug/ | python3 -m json.tool | head -20
```

列表和详情都应返回 JSON；详情多出 `body`、`body_html`、`toc`、`liked`。不带末尾斜杠的地址会被 Django 重定向，写前端请求时统一带 `/`。

## 验证

- `.venv/bin/python manage.py test blog.tests.ArticleApiTests` 覆盖列表形状、创建、权限、点赞、封面上传。
- 匿名 POST `/api/articles/` 应返回 401 或 403。
- 非作者 PATCH 应返回 403，作者和 staff 应返回 200。
- 删除后详情返回 404，列表的 `count` 减一。
- 自定义动作路径不要和 `{slug}` 冲突；`hot` 是 `detail=False`，所以放在列表层级。

## 踩坑与差异

- 原教程用 Django 通用视图 + 模板；这里用 DRF 的 ViewSet + 序列化器，返回 JSON，分派逻辑由框架做。
- `SimpleRouter` 不提供 API 根视图；需要可浏览的根入口时换 `DefaultRouter`。
- `lookup_value_regex` 不放宽的话，slug 里带点会匹配失败；放宽太多又会和动作路径打架，当前取的是折中值。
- `basename` 漏写会在启动时报错，这是 ViewSet 最常见的配置问题；改路由前缀时也要同步检查它，否则反向解析会指向旧名字。
- ViewSet 让文件变短，但把行为分散到多个动作里；读代码时要先看 `get_queryset` 和权限类，否则容易误判某个接口谁能调用。遇到 403，先确认是全局权限还是对象权限拒绝，再去看动作上的覆盖配置，同时保留请求日志方便复现。

如果只用 `APIView`，每个动作都要自己写 `get/post/patch/delete`，还要重复查对象、跑序列化器、处理 404。ViewSet 把这些固定流程交给框架，自己只保留真正不同的部分：查询集、权限和自定义动作。代价是“看不见的代码”变多，调试时要熟悉 DRF 的调用链，尤其是 `get_object`、`get_serializer` 和 `check_object_permissions` 的先后顺序。

ViewSet 把文章相关动作收拢了。下一章给文章加栏目，用外键归档，并让列表、写作页和侧栏都能用上。
