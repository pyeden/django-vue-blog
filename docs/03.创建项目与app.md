# 03. 创建项目与 app

## 本章目标
- 在 `backend/` 下用 `config` 配置包建立 Django 4.2 项目。
- 按领域创建 `blog`、`accounts`、`comments`、`notices` 四个 app。
- 在 `INSTALLED_APPS` 和根路由里注册它们。
- 用 `check` 与迁移状态确认项目能跑。

## 原教程怎么做
原教程在 Windows 的虚拟环境里执行 `python manage.py startapp article`，只建一个 `article` 应用，文章、后台、视图都放进去；然后改 `my_blog/settings.py` 的 `INSTALLED_APPS`，在 `my_blog/urls.py` 用 `include('article.urls')` 分发。

## 本实作怎么做
我没有把所有东西塞进一个 app。按职责拆开后，后面加评论、通知、用户资料时不用动文章代码：`blog` 管文章、栏目、点赞和 Markdown；`accounts` 管登录注册、资料和头像；`comments` 管两级评论；`notices` 管通知。配置包是 `backend/config/`，不是原教程的双层 `my_blog/`。

`backend/config/settings.py` 的 `INSTALLED_APPS` 末尾是：
```python
INSTALLED_APPS = [
    "rest_framework",
    "corsheaders",
    "taggit",
    "django_filters",
    "accounts",
    "blog",
    "comments",
    "notices",
]
```
`backend/config/urls.py` 把四组 URL 都挂在 `/api/` 下：
```python
urlpatterns = [
    path("admin/", admin.site.urls),
    path("api/health/", health, name="health"),
    path("api/", include("accounts.urls")),
    path("api/", include("blog.urls")),
    path("api/", include("comments.urls")),
    path("api/", include("notices.urls")),
]
```
`accounts/apps.py` 的 `ready()` 里导入了 `signals`，保证新建用户时自动建 `Profile`。这一点原教程没有，是后面注册和资料页的前提。

## 在 MacBook 上操作
仓库已经建好时，只需要激活环境并检查：
```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python --version
python manage.py check
python manage.py showmigrations --list
```
我实际得到的第一行是 `Python 3.12.2`，`check` 输出 `System check identified no issues (0 silenced).`。迁移列表里 `accounts`、`blog`、`comments`、`notices` 的 `0001_initial` 都是 `[X]`，说明四个 app 已建表。

如果从空目录重做，创建顺序是：
```bash
django-admin startproject config .
python manage.py startapp blog
python manage.py startapp accounts
python manage.py startapp comments
python manage.py startapp notices
python manage.py makemigrations
python manage.py migrate
```
注意 app 名字就是目录名，不要再用原教程的 `article`，否则后面所有 import 都会对不上。

## 验证
`python manage.py check` 无报错；`showmigrations` 四个业务 app 的首个迁移已应用；启动 `python manage.py runserver 127.0.0.1:8000` 后 `/admin/` 能打开登录页。做到这三步，项目骨架就算立住了。

## 踩坑与差异
- 原教程是单 app，本实作是四 app；`blog` 只负责文章与栏目，评论和通知各自独立。
- 原教程的配置包叫 `my_blog`，这里叫 `config`，`manage.py` 里是 `DJANGO_SETTINGS_MODULE=config.settings`。
- 原教程 `article/urls.py` 要写 `app_name`；这里用 DRF 的 `SimpleRouter`，注册时给 `basename="article"`。
- macOS 激活虚拟环境是 `source .venv/bin/activate`，不是 `env\Scripts\activate.bat`。除此之外本章没有遇到额外问题。

## 小结
骨架和路由都通了，下一步把文章、评论、用户资料写成模型，让数据库真正有结构。
