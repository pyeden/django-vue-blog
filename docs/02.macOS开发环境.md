# 02. macOS 开发环境

原教程的环境是 Windows 10 + Python 3.7 + Django 2.2。我在 MacBook 上的实际环境：

| 项 | 实际值 |
| --- | --- |
| 系统 | macOS 15.7.2（Apple Silicon） |
| Python | 3.12.2（Homebrew） |
| Django | 4.2 LTS |
| Node | 24.22.1 |
| npm | 11.19.1 |
| 数据库 | SQLite（Python 自带） |

## 1. 安装 Python

macOS 自带的 `python3` 版本太旧，不要用它建项目。用 Homebrew 装 3.12：

```bash
brew install python@3.12
/opt/homebrew/bin/python3.12 --version
# Python 3.12.2
```

> Intel Mac 的 Homebrew 前缀是 `/usr/local`，把上面的 `/opt/homebrew` 换掉即可。

## 2. 创建项目目录与虚拟环境

```bash
mkdir -p ~/work/django-vue-blog
cd ~/work/django-vue-blog
mkdir backend frontend docs deploy

cd backend
/opt/homebrew/bin/python3.12 -m venv .venv
source .venv/bin/activate
python --version
# Python 3.12.2
```

原教程用 `env\Scripts\activate.bat`，macOS 是 `source .venv/bin/activate`。激活后命令行前面会出现 `(.venv)`。

## 3. 安装 Django 与依赖

```bash
pip install "Django==4.2.*" djangorestframework django-taggit django-filter Pillow markdown bleach django-cors-headers gunicorn
```

> 原教程强调“必须锁定 Django 2.2”，否则会装到 Django 3。现在同理：锁 4.2 LTS，不追最新大版本，避免教程代码和框架一起漂移。

## 4. 创建 Django 项目

```bash
django-admin startproject config .
python manage.py runserver 127.0.0.1:8000
```

浏览器打开 <http://127.0.0.1:8000>，看到小火箭就成功了。

项目结构：

```text
backend/
├── manage.py
├── config/
│   ├── settings.py
│   ├── urls.py
│   └── wsgi.py
└── .venv/
```

原教程把项目也放在 `django_project/my_blog/my_blog/` 双层目录里；这里直接在 `backend/` 下用 `config` 作为配置包，少一层嵌套。

## 5. 前端环境

```bash
cd ../frontend
npm create vite@latest . -- --template vue
npm install
npm install axios pinia vue-router bootstrap bootstrap-icons marked dompurify highlight.js
npm run dev
```

Vite 默认跑在 <http://127.0.0.1:5173>。开发时把 `/api` 代理到 Django 的 8000 端口，生产构建时再改成 `/djangovueblog/api`。

## 6. 我实际踩到的坑

- **端口被占用**：Mac 上 8000 常被其他服务占用，换 `python manage.py runserver 127.0.0.1:8001`。
- **`source` 找不到**：确认当前目录是 `backend/`，虚拟环境目录叫 `.venv` 而不是 `venv`。
- **Node 版本**：Vite 5 要求 Node 18+；这台机器是 24，没问题。
- **中文路径**：项目放在 `~/work` 下，避免 iCloud 同步目录和空格路径，减少文件监听问题。
