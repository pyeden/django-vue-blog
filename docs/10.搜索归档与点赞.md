# 10. 搜索、归档与点赞

## 这一章解决什么

让文章不只靠“最新”被发现：可以搜、可以按栏目和标签归档，也可以看到最热和点赞。

## 搜索

DRF 的 `SearchFilter` 声明字段：

```python
search_fields = ["title", "body"]
```

前端发 `?search=keyword`，后端对标题和正文做 `icontains`。搜索结果复用 `ArticleFeed`，只改 `filters`，页面结构不变。

搜索用 GET，不用 POST：结果可缓存、可分享、刷新不重复提交。没有结果时显示空状态，不显示“错误”。

## 栏目与标签

栏目是 `ArticleColumn` 外键，标签用 taggit。列表接口同时支持：

```python
if column:
    queryset = queryset.filter(Q(column__slug=column) | Q(column__id=column))
if tag:
    queryset = queryset.filter(Q(tags__name__iexact=tag) | Q(tags__slug__iexact=tag)).distinct()
```

标签同时接受 name 和 slug，并且大小写不敏感。`Django` 的 slug 是 `django`，侧栏点进来不能查不到。

前端 `ColumnView`、`TagView` 只是 `ArticleFeed` 的薄包装：从路由拿 slug，传给 `filters`。

## 浏览量

详情接口用 `F()` 原子自增：

```python
Article.objects.filter(pk=instance.pk).update(total_views=F("total_views") + 1)
```

不要先 `instance.total_views += 1` 再 `save()`，并发会丢计数。这个计数按请求累加，不做用户去重；个人博客够用，也能反映真实访问热度。

## 点赞

点赞要求登录，模型有唯一约束：

```python
like, created = ArticleLike.objects.get_or_create(article=article, user=request.user)
if created:
    Article.objects.filter(pk=article.pk).update(likes=F("likes") + 1)
else:
    like.delete()
    Article.objects.filter(pk=article.pk, likes__gt=0).update(likes=F("likes") - 1)
```

返回 `{liked, likes}`。重复点只会在“点过/没点过”之间切换，不会把计数刷上去。

## 最热

`/api/articles/hot/` 按 `total_views` 取前 5，侧栏直接用。热门是“被发现”的辅助路径，不替代首页。

## 验证

- `?search=Markdown` 返回匹配文章。
- `/column/tech/`、`/tag/django/` 正常。
- 同一用户连点两次赞，计数回到原值。
- 刷新详情，浏览量递增。

发现路径越多，读者越容易留下来。但每一路都要复用同一套列表组件，避免五个页面五套逻辑。下一章写测试与日志。
