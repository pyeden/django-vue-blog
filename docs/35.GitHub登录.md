# 35. GitHub 登录

## 本章目标

- 说清本实作当前的登录方式与边界。
- 核实 GitHub OAuth 到底有没有接入。
- 解释为什么没有启用，而不是假装已经上线。
- 给出以后要接时可以照着走的方案。

## 原教程怎么做

原教程安装 `django-allauth`，注册 `allauth`、`allauth.account`、`allauth.socialaccount` 和 `allauth.socialaccount.providers.github`，配置 `SITE_ID`、认证后端和登录跳转地址，再在 GitHub 上创建 OAuth App，把 Client ID 与 Secret 填进后台。

## 本实作怎么做

**本实作没有启用 GitHub OAuth。** 当前只有本地账号体系：`accounts` app 提供注册、登录、退出、当前用户、密码重置和注销账号，认证方式是 Django Session + CSRF，DRF 侧只启用了 `SessionAuthentication`。

这不是“代码写了但没开”，而是依赖根本没有装。`backend/requirements.txt` 里没有 `django-allauth`，`config/settings.py` 的 `INSTALLED_APPS` 里没有 `allauth`，`config/urls.py` 里也没有社交登录路由。登录页只有用户名和密码表单，没有“使用 GitHub 登录”按钮。

没有启用的原因有三个，都是实际约束：

1. **Mac mini 直连 GitHub 被墙。** OAuth 不只是浏览器跳转，服务端还要拿 `code` 去 `github.com/login/oauth/access_token` 换 token。部署机连不上 GitHub，回调阶段就会卡住；靠浏览器能打开 GitHub 不代表服务器能完成换取。
2. **子路径部署让回调地址变复杂。** 站点挂在 `https://seres-ai.com/djangovueblog/`，OAuth App 的 Authorization callback URL 必须精确匹配，还要处理 SPA 的登录后跳转、`LOGIN_REDIRECT_URL` 和 CSRF 信任源。
3. **多一套账号合并规则。** GitHub 返回的邮箱可能为空或与本地账号重复，需要决定“自动合并”还是“要求先登录再绑定”。这属于产品决策，不是装个库就结束。

所以本章的诚实结论是：**未启用，可选，未验证。**

## 在 MacBook 上操作

先核实依赖确实不存在：

```bash
cd ~/work/django-vue-blog/backend
grep -in "allauth\|social" requirements.txt config/settings.py
```

实际没有匹配，命令会输出：

```text
NO_ALLAUTH_MATCH
```

再确认模块不可导入：

```bash
source .venv/bin/activate
python -c "import allauth"
```

实际报错是：

```text
ModuleNotFoundError: No module named 'allauth'
```

这两条比“我记得没装”可靠。

## 验证

当前登录链路的验证不依赖 GitHub，跑账号测试即可：

```bash
python manage.py test accounts
```

实际输出末尾是：

```text
Ran 12 tests in 1.081s

OK
```

覆盖注册、密码不一致、登录退出、错误密码、匿名 `me`、CSRF cookie、资料权限、资料修改、头像上传和重置密码恒定 200。登录页能正常工作是现状，不是本章新增功能。

如果要接 GitHub，验收至少应包括：未登录点按钮能跳转 GitHub；授权后回站建立 session；`/api/auth/me/` 返回用户；取消授权不留半截账号；同一 GitHub 账号二次登录不重复建用户。以上均**尚未执行**。

## 踩坑与差异

回调地址是最容易错的一项。`django-allauth` 默认按站点根路径拼回调，子路径部署时要显式配置 `LOGIN_REDIRECT_URL`、`ACCOUNT_LOGIN_REDIRECT_URL`，并在 GitHub OAuth App 里填完整路径。路径多一个斜杠就会 `redirect_uri` 不匹配。

第二个坑是网络。即使 MacBook 能访问 GitHub，生产回调发生在 Mac mini，换取 token 的请求也从那里发出。要么给 Mac mini 配可用的出站代理，要么把 OAuth 换取放到一台能直连的中间服务，后者会引入新的信任边界。

第三个坑是账号合并。建议第一版采用“只允许已有本地账号绑定 GitHub”，不做自动注册，避免邮箱相同就合并带来的接管风险。等绑定流程稳定，再开放 GitHub 首次注册。

## 小结

这一章没有交付一个登录按钮，但把“为什么没有”写清楚了。下一章换到能实际跑起来的部分：五十个自动化测试。
