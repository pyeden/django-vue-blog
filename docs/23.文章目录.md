# 23. 文章目录

## 本章目标

- 从 Markdown 源里提取标题层级，而不是用正则自己扫。
- 把目录作为文章详情 API 的一部分返回，前端不用重复解析正文。
- 用 `TocRail` 渲染目录，并用 `IntersectionObserver` 做滚动高亮。
- `TocRail` 对 h1–h6 做观察，目录里的层级与滚动高亮一致。

## 原教程怎么做

原教程用 Python-Markdown 的 `toc` 扩展，在文章正文里写 `[TOC]` 标记，渲染时自动替换成目录。它还会讲标题 id 是怎么生成的，以及如何用 CSS 把目录固定在侧边。目录和正文在同一次模板渲染里完成，前端不需要额外的数据结构。

## 本实作怎么做

渲染和提取都在 `backend/blog/utils.py`。`MD_EXTENSIONS` 包含 `toc`，配置深度为 1–6：

```python
"toc": {"permalink": False, "toc_depth": "1-6"},
```

`extract_toc()` 不解析生成的 HTML，而是让 `markdown.Markdown` 转换一次，再遍历 `md.toc_tokens`：

```python
def walk(tokens):
    for token in tokens:
        toc.append({
            "level": token.get("level", 1),
            "text": token.get("name", ""),
            "anchor": token.get("id", ""),
        })
        walk(token.get("children", []))
```

返回的是扁平数组 `[{level, text, anchor}]`，保留文档顺序。前端渲染时用 `level` 控制缩进，比嵌套树更好写样式。

`ArticleSerializer` 的 `get_toc` 调用 `extract_toc(obj.body)`，所以详情接口天然带 `toc`。正文 `body_html` 由 `render_markdown()` 生成，`toc` 扩展会给每个标题加 `id`，`bleach` 的允许属性里保留了 `id`，锚点才能用。

前端 `frontend/src/views/ArticleDetailView.vue` 把 `article.toc` 传给 `TocRail`。`TocRail.vue` 在挂载后查询 `.article-body .prose` 下的 `h1[id]` 到 `h4[id]`，用 `IntersectionObserver` 观察：

```js
observer = new IntersectionObserver(
  (entries) => {
    const visible = entries
      .filter((entry) => entry.isIntersecting)
      .sort((a, b) => a.boundingClientRect.top - b.boundingClientRect.top)
    if (visible[0]) active.value = visible[0].target.id
  },
  { rootMargin: '-90px 0px -70% 0px', threshold: [0, 1] }
)
```

点击目录项时 `scrollTo(anchor)` 调 `scrollIntoView`，并立即把该项设为激活。路由的 `scrollBehavior` 也支持 `to.hash`，所以带锚点的链接刷新后能定位。


应能看到 `level`、`text`、`anchor` 三个字段。前端打开详情页，右侧应出现“本文目录”，滚动正文时对应项会变亮。

## 验证

- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_author_can_create_with_tags_and_column` 里断言了 `len(data["toc"]) == 1`，说明目录随详情返回。
- 正文里写 `## 一级`、`### 二级`，接口的 `level` 应分别是 2、3。
- 点击目录项，页面会平滑滚到对应标题；直接访问带 `#anchor` 的链接也能定位，因为路由的 `scrollBehavior` 处理了 `to.hash`。
- 把某篇文章的标题改成重复文本，Markdown 会生成不同的 id，目录不会互相跳错。

## 踩坑与差异

- 原教程在正文里放 `[TOC]` 占位；这里不在正文里插目录，而是把结构单独返回，正文保持干净。
- 早期版本 `TocRail` 只覆盖 h1–h4，而 `toc_depth` 是 1–6；现已把选择器补全到 h1–h6，避免“目录里有但点不亮”的不一致。
- `bleach` 如果没保留 `id` 属性，正文标题的锚点会被清掉，目录点击就找不到元素。这个问题很隐蔽，改清洗规则时要回归。
- 滚动高亮的 `rootMargin` 是经验值，顶栏高度变了要跟着调，否则激活项会慢半拍。
- 目录没有做“当前项自动滚入可视区域”，目录很长时激活项可能跑到视口外。

目录和正文的标题 id 必须来自同一次 Markdown 渲染规则，否则会出现“目录有项、页面找不到锚点”。当前两者都用 `MD_EXTENSIONS` 和 `MD_EXTENSION_CONFIGS`，所以能对上。以后若换渲染器或改清洗规则，要同时检查 `extract_toc` 和 `render_markdown`，不要只改一边。

手机屏幕窄，右侧目录会被布局隐藏，读者主要靠正文标题本身导航。这个取舍是有意的：小屏优先保证正文宽度，不强行塞一个会遮挡内容的浮层。若以后要在移动端提供目录，更适合做成可展开的底部抽屉，而不是直接复用桌面侧栏。
