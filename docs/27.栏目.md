# 27.栏目

## 本章目标

- 建立 `ArticleColumn` 模型，让文章可以归到一个栏目，也可以暂时不归。
- 理解 `on_delete=SET_NULL` 和 `CASCADE` 的区别，选择不连带删文章。
- 提供栏目列表接口，带每栏文章数，供侧栏和归档页使用。
- 让写作页能选栏目，列表能按栏目过滤。

## 原教程怎么做

原教程新增 `ArticleColumn` 模型，字段是标题和时间，然后在文章模型里加外键。它先注册 admin 方便造测试数据，再改文章列表视图，把栏目一起查出来显示；写文章和更新文章的表单也要加栏目选择。原教程还会提醒：栏目删除时文章怎么办，要在 `on_delete` 上做决定。

## 本实作怎么做

模型在 `backend/blog/models.py`：

```python
class ArticleColumn(models.Model):
    title = models.CharField(max_length=100)
    slug = models.SlugField(max_length=120, unique=True)
    created = models.DateTimeField(auto_now_add=True)
```

文章外键：

```python
column = models.ForeignKey(
    ArticleColumn,
    on_delete=models.SET_NULL,
    null=True,
    blank=True,
    related_name="articles",
)
```

`SET_NULL` 表示栏目被删后文章还在，只是变成“未分类”；如果用 `CASCADE`，删一个栏目会连带删掉所有文章，对博客太危险。`null=True` 允许文章没有栏目，`related_name="articles"` 让栏目能反查自己的文章。

写入时前端传的是栏目 slug，所以序列化器自定义了 `ColumnField`：读的时候返回 `{title, slug}`，写的时候同时接受 slug 和数字 id：

```python
query = Q(slug=str(data))
if str(data).isdigit():
    query |= Q(pk=int(data))
column = ArticleColumn.objects.filter(query).first()
```

找不到就报“栏目不存在”，不会静默存成空。文章列表的 `get_queryset()` 读 `?column=`，同样兼容 slug 和 id，再过滤。

栏目列表在 `ArticleColumnListView`，用 `annotate(article_count=Count("articles"))` 一次算出每栏文章数，按标题排序，不分页。前端 `SidebarPanel.vue` 显示栏目和数量，`ColumnView.vue` 用 `/column/:slug` 复用 `ArticleFeed`，把 `column` 作为过滤条件。

写作页 `ArticleEditor.vue` 从 `meta.columns` 生成下拉框，提交时把 `form.column`（slug 或空字符串）放进 payload；空字符串在序列化器里会被当成 `None`。

## 在 MacBook 上操作

```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py runserver 127.0.0.1:8000
```

先在 admin 的 `ArticleColumn` 里加两个栏目，例如“技术”“随笔”，slug 分别填 `tech`、`essay`。然后：

```bash
curl -s http://127.0.0.1:8000/api/columns/ | python3 -m json.tool
```

返回数组，每项包含 `title`、`slug`、`article_count`。前端首页侧栏应出现栏目列表，点进去能看到该栏文章。

## 验证

- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_column_and_tag_filter`：按 `?column=tech` 过滤应只剩该栏文章。
- 新建文章时选栏目，详情返回的 `column` 应是 `{"title": "...", "slug": "..."}`。
- 不选栏目，`column` 应为 `null`，列表页显示“随笔”或不显示栏目名。
- 在 admin 删除栏目，文章仍在，`column` 变成 `null`，这验证了 `SET_NULL`。

## 踩坑与差异

- 原教程在模板里显示栏目；这里由 `ColumnField` 决定 JSON 形状，前端不用再查一次栏目表。
- 栏目 slug 必须唯一，admin 的 `prepopulated_fields` 会从标题生成，但中文标题生成的 slug 可能需要手动改。
- `article_count` 统计的是全部文章，不按发布时间或草稿状态过滤；当前没有草稿概念，所以没问题。
- 写作页提交空字符串表示“未分类”，不要传 `0`；`ColumnField` 把 `0` 也当空，但语义上容易混淆。
- 删除栏目不会删文章，这是产品选择；如果以后要做“栏目必须存在”，得把 `null` 改成 `False` 并处理历史数据。

栏目数据由 `meta` store 缓存，首页、写作页、侧栏共用一份，避免每个组件各请求一次。`meta.load()` 默认只加载一次，新增栏目后要刷新页面或手动 `load(true)` 才会更新。这个取舍适合变化不频繁的分类数据；如果栏目经常调整，应该改成每次进入写作页强制刷新。

## 小结

栏目解决“大分类”，标签解决“多对多的小主题”。下一章引入 `django-taggit`，让一篇文章可以挂多个标签。
