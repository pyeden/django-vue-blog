# 29. 封面图

## 本章目标

- 给 `Article` 加 `cover` 字段，理解 `upload_to` 和媒体目录的关系。
- 用 multipart 接口上传封面，并在创建、编辑两条路径上都能用。
- 在文章卡片和详情页展示封面，处理没有封面的布局。
- 知道当前没有压缩、裁剪和缩略图，原图直接进页面。

## 原教程怎么做

原教程先配好 `MEDIA_URL`、`MEDIA_ROOT`，在文章模型加 `ImageField`，然后讲怎么处理上传的图片：校验格式、限制大小、按比例缩放，避免用户传几兆的原图直接把列表拖慢。它还会用 `imagekit` 之类的库生成缩略图，并在模板里按场景取不同尺寸。编辑文章时也要能替换封面。

## 本实作怎么做

字段在 `backend/blog/models.py`：

```python
cover = models.ImageField(upload_to="covers/", blank=True, null=True)
```

`upload_to="covers/"` 让文件落在 `media/covers/`，`null=True` 表示封面可选。序列化器里 `cover = serializers.ImageField(required=False, allow_null=True)`，所以创建文章时可以直接用 multipart 把封面一起传；`ArticleCard.vue` 和详情页通过 `mediaUrl()` 取地址。

单独换封面的接口是 `ArticleViewSet` 上的动作：

```python
@action(
    detail=True,
    methods=["post"],
    url_path="cover",
    parser_classes=[MultiPartParser, FormParser],
    permission_classes=[permissions.IsAuthenticatedOrReadOnly, IsAuthorOrStaff],
)
def cover(self, request, slug=None):
    article = self.get_object()
    self.check_object_permissions(request, article)
    file = request.FILES.get("cover")
    ...
    article.cover = file
    article.save(update_fields=["cover"])
```

`parser_classes` 必须声明，否则 DRF 只按 JSON 解析，`request.FILES` 会是空的。`check_object_permissions` 保证只有作者或 staff 能换封面。

封面地址在开发环境由 Django 返回，部署到子路径后则由 `VITE_MEDIA_BASE` 或 nginx 的媒体前缀决定。前端 `mediaUrl()` 同时兼容绝对地址、协议相对地址和以斜杠开头的路径，避免开发和生产的图片地址写法不一致。这个函数看起来不起眼，却是部署后图片能否显示的关键。

前端 `ArticleEditor.vue` 的保存顺序是“先创建/更新文章，再上传封面”：拿到 `saved.slug` 后调用 `uploadArticleCover(saved.slug, coverFile)`。这样新建文章时也能复用同一个封面接口，不需要在创建请求里拼 multipart。`CoverUpload.vue` 用 `URL.createObjectURL` 做本地预览，组件卸载时 `revokeObjectURL`，避免内存泄漏。

`ArticleCard.vue` 有封面时显示横图，没有封面时加 `no-cover` 类走纯文字布局；详情页的封面限制最大高度并 `object-fit: cover`，不让长图把正文挤到屏幕外。

## 验证

- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_cover_upload_on_create`：创建时带封面，返回的 `cover` 应包含 `/media/covers/`，数据库里字段不为空。
- 编辑已有文章，只换封面不改正文，详情页图片应更新。
- 非作者调用 `/api/articles/{slug}/cover/` 应返回 403。
- 不上传封面，文章仍能正常创建和显示，卡片走无图布局。

## 踩坑与差异

- 原教程用 imagekit 做缩略图；这里没有引入，列表直接用原图。图片大时首页会明显变慢，这是当前实现的短板。
- 前端是“先存文章再传封面”，如果封面上传失败，文章已经创建成功，用户会看到“保存失败”但文章其实存在。更稳的做法是先提示“文章已保存，封面上传失败”，或把封面放进创建请求。
- 旧封面不会删除，换图后 `media/covers/` 会留下孤儿文件。
- 没有限制文件大小和尺寸，`ImageField` 只验证是不是图片；生产环境要在 nginx 设 `client_max_body_size`，后端再加校验。
- 生产环境图片由 nginx 的 `alias` 提供，Django 的 `static()` 只在 `DEBUG=True` 时挂载；忘记配 nginx 会出现 API 正常、图片 404。

## 小结

封面是列表页的第一视觉入口，但也要照顾没有图片的文章。下一章处理正文编辑，把 Markdown 编辑器、实时预览和工具栏串起来。
