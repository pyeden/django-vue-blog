# 10. 写作与发布

## 本章目标
- 用 `ArticleEditor` 完成标题、正文、栏目、标签和封面输入。
- 让创建接口把作者绑定为当前登录用户。
- 理解标签与栏目的写入方式。
- 把封面上传做成创建后的独立请求。

## 原教程怎么做
原教程写 `ArticlePostForm`，只包含 `title`、`body` 两个字段；`article_create()` 在 POST 时校验表单，`save(commit=False)` 后把作者固定成 `User.objects.get(id=1)`，再保存并跳回列表。模板是普通的 `<form method="post">`。

## 本实作怎么做
创建接口由 `ArticleViewSet` 的 `create` 提供，权限是 `IsAuthenticatedOrReadOnly` 加对象权限，所以匿名 POST 会被拒绝。序列化器在 `backend/blog/serializers.py` 里把作者从请求上下文取出来：
```python
def create(self, validated_data):
    tags = validated_data.pop("tags", [])
    request = self.context["request"]
    article = Article.objects.create(author=request.user, **validated_data)
    article.tags.set(tags)
    return article
```
`column` 字段接受栏目 slug 或数字 id，写入前会查 `ArticleColumn`；`tags` 接受字符串数组，去重后交给 `django-taggit`。`slug` 是只读字段，由模型自动生成。

前端写作页是 `frontend/src/views/WriteView.vue`，核心组件 `frontend/src/components/ArticleEditor.vue`。保存时先创建文章，再单独上传封面：
```js
const payload = {
  title: form.title.trim(),
  body: form.body,
  column: form.column || null,
  tags: form.tags,
}
const saved = isEdit.value
  ? await updateArticle(props.article.slug, payload)
  : await createArticle(payload)
if (coverFile.value) {
  await uploadArticleCover(saved.slug, coverFile.value)
}
```
封面上传是 `POST /api/articles/<slug>/cover/`，对应 `ArticleViewSet.cover` 这个 `@action`，解析器是 `MultiPartParser` 和 `FormParser`。`CoverUpload.vue` 只做本地预览和把 `File` 交给父组件，真正上传发生在保存时。

编辑器的工具栏不是富文本，它只是往 textarea 的光标位置插入 Markdown 记号：`wrap()` 处理选中文本，`insertBlock()` 处理代码块、引用、列表这类块级内容。表单用 `reactive` 保存 `title`、`body`、`column`、`tags`，预览用 `renderMarkdown(form.body)` 实时算，不请求后端。栏目下拉的数据来自 `meta` store，标签输入用 `TagInput`，封面用 `CoverUpload` 只做本地预览。

## 在 MacBook 上操作
先登录，再打开 <http://127.0.0.1:5173/write>。填标题、选栏目、加标签、写正文，点“发布文章”。如果要用接口调试，先拿 CSRF Cookie，再发 JSON：
```bash
curl -s -c /tmp/blog-cookies.txt http://127.0.0.1:8000/api/auth/csrf/
curl -s -b /tmp/blog-cookies.txt -H "X-CSRFToken: <cookie里的值>" \
  -H "Content-Type: application/json" \
  -d '{"title":"接口测试","body":"# 你好","tags":["测试"]}' \
  http://127.0.0.1:8000/api/articles/
```
没有登录或没有 CSRF 头时，接口会返回 401/403，这是预期行为。

保存前先检查标题和正文非空，再决定走创建还是更新。创建成功后返回的 `saved` 里有服务端生成的 `slug`，封面请求必须用这个 slug，不能用标题拼。封面接口单独设了 `MultiPartParser`，所以它接受 `FormData`；创建接口默认也支持 JSON 和 multipart，但前端把创建和封面拆成两步，封面失败时还能回编辑页补传。两个请求都走 axios 的 CSRF 拦截器。

## 验证
发布成功后应跳到 `/article/<slug>`，标题、正文、标签、栏目都在；如果选了封面，图片地址在 `/media/covers/` 下。`backend/blog/tests.py` 的 `test_author_can_create_with_tags_and_column` 验证标签和栏目，`test_cover_upload_on_create` 验证封面，`test_anonymous_cannot_create` 验证匿名拦截。

如果发布后跳转 404，先看返回的 `saved.slug` 是否为空；正常由模型生成，不会为空。封面请求 403 时检查 CSRF cookie 和登录态，封面 action 也走对象权限，不是只靠前端按钮。

## 踩坑与差异
- 原教程把作者写死成 id=1；本实作从 `request.user` 取，换账号发文不会串作者。
- 前端的封面不是在创建请求里一起传，而是“创建成功后再上传”。如果封面失败，文章已经存在，需要回编辑页补传；这样做是为了失败可恢复，不必重写正文。
- 标签在前端 `TagInput` 里最多保留 10 个，回车或逗号确认；后端仍会去重。
- 正文和标题都必填，空字符串会在前端先被拦下。
- 工具栏的 `wrap()` 依赖 `textarea.selectionStart`，焦点不在正文框时点击按钮不会插入内容，先点正文再点工具。
- 创建接口其实也支持 multipart 单请求带封面，测试 `test_cover_upload_on_create` 走的是这条；前端拆两步是为了失败后能补传。

## 小结
文章能写、能带标签和封面发布，下一步处理“删文章”这种危险操作，把权限和确认做扎实。
