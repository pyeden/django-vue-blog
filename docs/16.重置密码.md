# 16. 重置密码

## 本章目标

- 理解为什么重置密码要走邮箱令牌，而不是让用户直接改：能拿到邮箱的人，才应该能改密码。
- 用 Django 自带的 `default_token_generator` 实现“申请重置”和“确认重置”两个 API，不引入额外第三方库。
- 在开发环境用 console 邮件后端看到完整的重置邮件，知道生产环境要换成 SMTP。
- 知道申请页与确认页都已实现：邮件链接带 uid/token，前端进入确认模式后设置新密码。

## 原教程怎么做

原教程先介绍 Django 内置的密码重置视图，讲清楚“发邮件、点链接、填新密码”的四步流程，然后引入 `django-password-reset` 第三方库，直接复用它的 URL、表单和邮件模板。这样做省事，但页面长什么样、邮件文案怎么写，基本都由库决定，想改成自己站点的风格要覆写一堆模板。原教程的重心因此落在“怎么配置第三方库”，而不是“重置令牌到底怎么工作”。

## 本实作怎么做

前后端分离后，重置流程拆成两个 JSON 接口，都在 `backend/accounts/views.py`。第一个 `PasswordResetView` 接收邮箱，查出 `is_active=True` 的用户，用 `default_token_generator.make_token()` 生成一次性令牌，再用 `urlsafe_base64_encode` 把用户主键编码成 uid。邮件正文里放的是 `uid-token` 组合，前端不需要知道用户 id 是什么。

```python
uid = urlsafe_base64_encode(force_bytes(user.pk))
token = default_token_generator.make_token(user)
send_mail(
    subject="密码重置",
    message=f"你的密码重置标识为：{uid}-{token}",
    recipient_list=[user.email],
    fail_silently=True,
)
```

第二个 `PasswordResetConfirmView` 做三件事：解码 uid 找到用户、用 `check_token` 验证令牌、用 `validate_password` 检查新密码强度后 `set_password`。令牌和用户当前的密码哈希、最后登录时间绑定，所以密码一旦改过，旧令牌自然失效，不需要自己维护过期表。

路由在 `backend/accounts/urls.py`：

```python
path("auth/password-reset/", PasswordResetView.as_view()),
path("auth/password-reset/confirm/", PasswordResetConfirmView.as_view()),
```

前端 `frontend/src/views/ResetPasswordView.vue` 只调用 `passwordResetRequest(email)`，成功后显示“邮件已发送”。确认接口 `passwordResetConfirm` 已经在 `frontend/src/api/index.js` 里，但还没有对应的路由页面；目前只能用 curl 或 DRF 可浏览 API 完成最后一步。这一点我在文档里明确写出来，不假装它已经完整。

开发环境邮件后端在 `backend/config/settings.py`：

```python
EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend"
```

所以邮件不会真的发出去，而是打印在 runserver 的终端里。生产环境把 `DJANGO_EMAIL_BACKEND` 换成 SMTP 后端，再补用户名、授权码和端口即可。

## 在 MacBook 上操作

```bash
cd ~/work/django-vue-blog/backend
source .venv/bin/activate
python manage.py runserver 127.0.0.1:8000
```

另开一个终端请求：

```bash
curl -i -X POST http://127.0.0.1:8000/api/auth/password-reset/ \
  -H 'Content-Type: application/json' \
  -d '{"email":"你的注册邮箱"}'
```

接口固定返回 200 和“若该邮箱已注册，重置邮件已发送。”，runserver 终端会打印邮件正文。复制里面的 `uid-token`，再请求：

```bash
curl -i -X POST http://127.0.0.1:8000/api/auth/password-reset/confirm/ \
  -H 'Content-Type: application/json' \
  -d '{"uid":"...","token":"...","password":"NewPass12345"}'
```

如果密码太短或太常见，接口返回 400，并在 `password` 字段里给出具体原因；这是 `validate_password` 的输出，不是随便一句“失败”。

## 验证

- 邮箱不存在时也返回 200，避免接口被用来枚举哪些邮箱注册过。
- 同一个 token 第二次提交会返回 400“重置链接已失效”，说明令牌确实是一次性的。
- 自动化测试：`.venv/bin/python manage.py test accounts.tests.AuthApiTests.test_password_reset_always_200`。整个后端当前 50 个测试全部通过。
- 重置后用新密码调用 `/api/auth/login/` 应成功，用旧密码应返回 400。

## 踩坑与差异

- `User.email` 允许为空；没有邮箱的账号收不到重置信，注册页应尽量要求邮箱。
- `send_mail(..., fail_silently=True)` 会吞掉 SMTP 错误，开发时容易以为发出去了，其实只有 console 后端下能在终端看到。
- 原教程用第三方库把模板一起给了；这里只复用 Django 的 token 机制，邮件文案和接口形状都由自己控制，确认页由前端 `ResetPasswordView` 的确认模式处理。
- 邮件里的标识格式是 `uid-token`；生产环境建议改成可点击链接，并配置 SMTP。
- 邮件里目前只给标识，不给可点击的绝对链接。若要做一键重置，需要把 `FRONTEND_BASE_URL` 拼进正文。

## 小结

重置密码只依赖 User 本身。下一章扩展 User，用一对一 `Profile` 存电话、简介和头像，为头像上传做准备。
