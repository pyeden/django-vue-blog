# 21.最热文章

## 本章目标

- 用浏览量作为热度指标，取出前五篇文章。
- 理解为什么不该为“最热”再复制一套列表视图和路由。
- 用 DRF 的 `@action` 在现有 `ArticleViewSet` 上挂一个只读动作。
- 在首页侧栏用 `SidebarPanel` 展示最热列表，并处理加载失败和空数据。

## 原教程怎么做

原教程没有新建视图，而是改造文章列表视图：读 `request.GET.get('order')`，等于 `total_views` 时用 `order_by('-total_views')`，否则保持默认排序，再把 `order` 传进模板。模板里的“最热”按钮和分页链接都带上 `order` 参数，翻页时才不会丢失排序。它强调“重复的代码是万恶之源”，所以把排序合并进原列表，而不是复制一份。

## 本实作怎么做

本实作把“最热”做成 `ArticleViewSet` 上的自定义动作，位置在 `backend/blog/views.py`：

```python
@action(detail=False, methods=["get"], url_path="hot")
def hot(self, request):
    articles = self.get_queryset().order_by("-total_views")[:5]
    serializer = self.get_serializer(articles, many=True)
    return Response(serializer.data)
```

`detail=False` 表示它不针对某一篇文章，路由是 `/api/articles/hot/`；`methods=["get"]` 限定只读。它复用 `get_queryset()`，所以栏目、标签过滤和 `comment_count` 注解都还在，只是最后按浏览量倒序取五条。返回值直接是数组，不再包一层分页，前端拿到就能渲染。

同时，`ArticleViewSet` 声明了 `ordering_fields`，所以 `GET /api/articles/?ordering=-total_views` 也能得到按浏览量排序的完整分页列表。两种入口分工不同：`hot` 给侧栏固定五条，`ordering` 给需要翻页的“按热度浏览”页面。

前端 `frontend/src/components/SidebarPanel.vue` 在 `onMounted` 时调用 `fetchHotArticles()`：

```js
async function loadHot() {
  loadingHot.value = true
  try {
    hot.value = await fetchHotArticles()
  } catch (error) {
    toast.error('最热文章加载失败')
  } finally {
    loadingHot.value = false
  }
}
```

`fetchHotArticles` 在 `frontend/src/api/index.js` 里请求 `/articles/hot/`，并用 `unwrapList` 兼容数组和分页对象两种形状。侧栏用序号 `01`、`02` 排版，加载时显示骨架，空数据显示“还没有足够的数据”。

## 验证

- 先给几篇文章制造不同浏览量，再请求 `hot`，第一条应是浏览量最大的。
- `.venv/bin/python manage.py test blog.tests.ArticleApiTests.test_ordering_by_views` 验证 `ordering=-total_views` 的排序结果。
- 文章不足五篇时，接口返回实际数量，不补空位。
- 浏览量全为 0 时，顺序按数据库默认的 `-created` 兜底，不会报错。

## 踩坑与差异

- 原教程把排序塞进列表视图并用 `order` 参数贯穿分页；这里拆成独立动作，侧栏不用关心分页，逻辑更直白。
- `hot` 复用了 `get_queryset()`，如果请求里带了 `?column=xxx`，它也会受影响；当前前端调用不带参数，所以是全局最热。若要做“栏目内最热”，需要显式决定是否保留这个行为。
- 没有做缓存。每次打开首页都会查一次数据库；个人博客量级没问题，流量上来后应加短 TTL 缓存。
- 取五条是硬编码。要改成可配置，可以读查询参数，但必须限制上限，避免一次取太多。
- 如果两篇文章浏览量相同，顺序可能不稳定；需要更严格时可加 `-id` 作为次级排序。

侧栏的最热列表只是入口，不承担“按热度浏览全部文章”的职责。读者点进任意一篇后，仍会回到普通详情页；想继续看热门内容，可以再回首页。把入口做小、做快，比在侧栏塞一个完整列表更符合阅读节奏，也避免首页一次发出过多请求。
